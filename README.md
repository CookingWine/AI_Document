# AI_Document 项目总说明（零基础版）

> **这套说明写给谁**
> 没写过代码、但要用 AI 干活的人；以及第一次接手这个文件夹、想知道"这都是些什么"的人。
>
> **你需要会什么**
> 会打开文件夹、会双击一个文本文件、会复制粘贴。就这些。
>
> **读完你能**
> 用几句话向同事说清这个项目由哪几块组成、每一块解决什么问题；遇到具体困惑时，知道该翻哪个文件夹里的哪一篇。

## 一、这个项目是什么

**一句话**：它是一套"怎么跟 AI 协作"的说明书，外加一份"怎么把这种协作做成软件"的开发设计稿。

拆成三句话说：

1. 你已经在用 AI 了，但可能每次都从头交代："用中文""别加客套话""别动别的文件"——说完就忘，下次还得再说。
2. 这套文档把"交代"变成三种**能存下来的东西**：不许越过的边界（规矩）、一类活的固定做法（技能）、把活派出去并验收的方法（智能体）。
3. 再往前一步，AI 还得"够得着"外面的文件和系统——这是第四个文件夹（`AIMCP/`）讲的事；第五个（`AgentWorkbench/`）把上面这些落成代码，设计一个"AI 能改数据、但必须你点头才生效"的桌面工具。

所以它不是一本教程，而是**一套可以反复使用的工具书 + 一份可以照着写代码的设计图**。

> 小提示：整套文档都是普通的纯文本文件，后缀是 `.md`。
> `.md` 是"Markdown"的缩写，可以理解成**带几个简单符号的记事本文件**——行首写 `#` 就是标题，写 `-` 就是一条清单。用系统的"文本编辑"（Mac）或"记事本"（Windows）就能打开，不需要装任何软件。

## 二、一张图看懂

```
AI_Document/
│
├── README.md              ← 你在这里：全项目总入口
│
├── AIAgents/              ① 派活：怎么把一件事交给 AI 办、怎么验收
├── AISkill/               ② 做法：一类活怎么干，写成文件让它照着做
├── AIRule/                ③ 边界：不管干什么，哪些线绝对不能踩
├── AIMCP/                 ④ 接口：AI 通过什么标准去够到外部工具和数据
│
└── AgentWorkbench/        ⑤ 落地：把上面几样做成一个能运行的软件（开发文档）
```

前四个是"概念与方法"，第五个是"工程实现"。**前四个不写代码也能用**，第五个需要会 C#（一种编程语言）。

## 三、五个文件夹分别管什么

先记一句口诀：**规矩管边界，技能管做法，智能体管执行，MCP 管接口，工作台管落地。**

| 文件夹 | 一句话 | 它回答的问题 | 打个比方 |
| --- | --- | --- | --- |
| `AIAgents/` | 智能体使用说明 | "这活该不该交给 AI？怎么派？做完怎么验？" | 怎么带一个新同事干活 |
| `AISkill/` | 技能制作手册 | "这类活每次都要重说一遍，怎么让它记住？" | 给新人配一本岗位操作手册 |
| `AIRule/` | 规则写法说明 | "不管做什么，哪些事绝对不许发生？" | 厨房墙上贴的卫生守则 |
| `AIMCP/` | 模型上下文协议说明 | "AI 怎么接上外部工具、文件和系统？" | 统一的电源插口标准 |
| `AgentWorkbench/` | 软件开发文档 | "怎么把受控的 AI 改数据做成一个能演示的程序？" | 照着图纸盖一间样板房 |

这五样不是互相替代，而是层层配合。用一家餐厅打比方：

```
AIRule      = 墙上的卫生守则      —— 谁进厨房都得守，不用谁来喊
AISkill     = 一本菜谱            —— 做某道菜时才翻开
AIAgents    = 厨师本人            —— 真正动手的人
AIMCP       = 传菜窗口 / 进货接口  —— 让厨房和外部的世界连起来
AgentWorkbench = 一间样板厨房      —— 把上面这些真的搭出来给人看
```

判断问题出在哪一层，有个好用的口诀：

| 你看到的现象 | 多半是哪一层的问题 | 去哪个文件夹 |
| --- | --- | --- |
| 它动了不该动的东西、编了没有的数据 | 边界 | `AIRule/` |
| 它做出来的东西结构不对、每次都不一样 | 做法 | `AISkill/` |
| 它没做完、没人盯、验收不了 | 执行 | `AIAgents/` |
| 它根本够不到那个系统 / 连不上那个工具 | 接口 | `AIMCP/` |
| 要把它做成一个真的软件 | 落地 | `AgentWorkbench/` |

### 4.5 `AgentWorkbench/` —— 落地：把受控的 AI 改数据做成软件

### 4.6 根目录的其他东西

| 文件 / 文件夹 | 是什么 | 要不要管 |
| --- | --- | --- |
| `README.md` | 你正在读的这份总说明 | 新增或调整文件夹时回来改 |
| `.gitignore` | 告诉版本管理工具"这些文件不用记"的清单，比如系统自动生成的 `.DS_Store`、本地配置 | 一般不用动 |
| `.git/` | Git（版本管理工具）的存档目录，里面是每一次修改的历史快照 | **不要手动改**，用 Git 命令或图形界面操作 |
| `.workbuddy/` | 协作工具自动生成的本地工作数据（记忆、会话缓存等），已被 `.gitignore` 排除 | 不用管，**不要删** |

> 什么是 Git？可以理解成"给文件拍快照的存档机"。每拍一次叫一次**提交**，以后改坏了能退回去。仓库根目录下执行 `git log` 就能看到全部历史。

```
                    ┌──────────────────────────────┐
                    │  AIRule  边界：不许做什么      │
                    │  （一直在，自动生效）          │
                    └──────────────┬───────────────┘
                                   │ 约束

┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│ AISkill 做法      │─────▶│ AIAgents 执行     │─────▶│ AIMCP 接口        │
│ 这类活按什么步骤做 │      │ 把活派出去、盯完成 │      │ 怎么够到外部工具   │
└──────────────────┘      └──────────────────┘      └──────────────────┘
                                   │
                                   ▼
                    ┌──────────────────────────────┐
                    │  AgentWorkbench 落地          │
                    │  把上面几样做成可运行的程序    │
                    └──────────────────────────────┘
```

四条关系，记住就不会乱：

1. **规则是继承的，不用重复写。** 全局定了"数字必须有出处"，项目里就不用再写一遍；写两遍迟早改漏一处。
2. **技能是查的，不是一直念的。** 只有遇到对应类型的活才翻；规则是每次开工都要读的，所以规则要短。
3. **智能体是执行的，它不产生规矩。** 它按规矩和技能干活；干错了，先看是规矩缺了还是技能缺了。
4. **MCP 只负责"够得着"，不负责"做得对"。** 它把工具接到 AI 面前，用不用、怎么用、要不要确认，仍由规则、技能和产品自己决定。

## 七、改文档之前先看这几条约定

这五套文档有自己的"家规"，照着改才不会越改越乱。

1. **`README.md` 是唯一入口。** 任何人不该"从中间某篇开始摸索"；新增一篇，必须回入口的索引里加一行。
2. **一篇只讲一件事。** 想加的内容塞不进任何现有篇目，才新建文件。
3. **引用一律用相对路径。** 写 `../AISkill/README.md`，不写 `/Users/你/...`。绝对路径换台电脑就失效。
4. **术语只在一处定义。** 每套文档的 `09-术语表.md`（AgentWorkbench 是 `13-术语表.md`）是唯一权威，正文用词要跟它一致。
5. **改完记一笔。** `AISkill/` 有 `CHANGELOG.md`；其余用 Git 提交记录，提交信息写"改了什么"，不写"更新"。

## 九、常见问题

**Q1：我完全不懂技术，这套文档能看懂吗？**
能。`AISkill/`、`AIRule/`、`AIAgents/`、`AIMCP/` 四套都是按"零基础"写的，每个术语第一次出现时都会解释，并且配生活里的比方。`AgentWorkbench/` 是唯一需要编程基础的部分，可以先跳过。

**Q2：这些文档能直接给 AI 看吗？**
能，而且这正是它们的用法之一。把某一篇的全文复制进对话，加一句"以上是我的工作手册，请确认理解，接下来按它执行"，比口头交代有效得多。`AISkill/templates/SKILL-模板.md` 就是专门给这个用途准备的骨架。

**Q3：文件夹能改名吗？**
不建议。文档之间大量使用相对路径互相引用，改名会让链接全部失效。如果一定要改，需要同时改所有引用处，并用编辑器全局搜索确认没有漏网。

**Q4：为什么每个文件夹都有一个 `README.md`？**
`README` 是"读我"的意思，是约定俗成的入口文件名。打开任何一个文件夹，先看它，就知道这里有什么、该按什么顺序读。

**Q5：这套文档会过期吗？**
会。尤其 `AIMCP/`（协议标准在演进）和 `AgentWorkbench/`（软件版本在变）。判断一份文档是否还适用，先看它里面写的日期和版本号，再去官方文档核对。文档里凡是写"以官方说明为准"的地方，都不是客套话。

**Q6：我想加一个新主题，该放哪儿？**
先问自己：它讲的是边界、做法、执行、接口，还是落地？
对应 `AIRule/`、`AISkill/`、`AIAgents/`、`AIMCP/`、`AgentWorkbench/`。都不是，才考虑新建文件夹，并回来更新本页第二节和第四节的图与表。

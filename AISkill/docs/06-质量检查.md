---

## 6.1 好坏写法对照

左边是新手常写的样子，右边是改法。**对着自己的手册，逐行找有没有踩中左边。**

| 差的做法 | 好的做法 | 为什么 |
| --- | --- | --- |
| "帮我处理文档" | "把 PDF 发票按月份重命名，放进对应月份文件夹" | 具体到能验收 |
| "写得好一点" | "每段不超过 100 字，不用感叹号，语气正式" | "好"是主观的，标准要可量化 |
| 只写要做什么 | 同时写不要做什么 | AI 默认会"多加一点" |
| 全是形容词 | 给一段真实例子 | 例子比形容词有效十倍 |
| 一张纸写满三千字 | 正文精简，长内容放 `references/` | 太长会挤掉重点 |
| 引用文件写全路径 | 写 `references/xxx.md` | 换电脑还能用 |
| 一次管十件事 | 一个技能只干一件事 | 边界清楚才好用 |

---

## 6.2 三个"翻译"练习

"写得具体"这句话太抽象。看三个实际改法，你会立刻明白。

**练习一：把形容词换成数字**

| 改之前 | 改之后 |
| --- | --- |
| 简洁一点 | 每段不超过 3 句 |
| 正式一点 | 不用感叹号、不用网络用语、不用"我觉得" |
| 详细一些 | 每个结论后面跟一个数据或例子 |

**练习二：把抽象动作换成具体动作**

| 改之前 | 改之后 |
| --- | --- |
| 整理一下数据 | 删掉空行，日期统一成"2026-10-28"格式，金额保留两位小数 |
| 检查一下错误 | 逐条核对：数字是否和原表一致、有没有漏项、单位是否统一 |
| 优化一下措辞 | 长句拆成短句，每句不超过 25 字，删掉"非常""十分"这类程度词 |

**练习三：把"要什么"补上"不要什么"**

| 只写要什么 | 补上不要什么 |
| --- | --- |
| 写一份周报 | 不要写客套话、不要加总结段、不要编造未提供的数据 |
| 总结这份会议记录 | 不要逐字复述、不要加入个人判断、不要遗漏待办事项和负责人 |
| 改写这段产品说明 | 不要用行业术语、不要夸大功效、不要改掉价格数字 |

## 6.3 最终检查清单

做完打勾，全勾上就合格了：

- [ ] 能用一句话说清这个技能干什么
- [ ] 写了"什么时候用"，且列的是用户真会说的话
- [ ] 写了背景信息（AI 不知道的事）
- [ ] 步骤是一步一个动作，不是笼统目标
- [ ] 写了至少三条"不要做什么"
- [ ] 有一个完整的"输入 → 输出"例子
- [ ] 引用文件用相对路径
- [ ] 自己真跑过一遍，结果符合预期
- [ ] 写了版本号和修改记录

---

## 6.4 每项怎么验

清单不是打勾就完事，要知道怎么判断真的过了。

| 检查项 | 怎么验 |
| --- | --- |
| 一句话说清干什么 | 读给不了解这事的同事听，他能复述出来 |
| "什么时候用"写得对 | 列出的话，和你平时真实会说的对得上 |
| 背景信息 | 假设一个陌生人接手，他照着手册能不能做 |
| 步骤可执行 | 每步都能回答"做完这步，桌上应该多出什么东西" |
| 至少三条禁止 | 回想上次 AI 让你不满意的地方，是不是都覆盖了 |
| 有例子 | 例子是真实产出，不是自己编的理想状态 |
| 相对路径 | 把文件夹整体移到别处，链接还能不能打开 |
| 真跑过 | 有没有实际试过一次，而不是"觉得应该行" |
| 版本号 | 文件开头有没有写第几版、什么时候改的 |

---

## 6.5 不合格的典型样子

如果你的手册长下面这样，回去改。

**样子一：像许愿**

```
帮我写一份好的周报，要专业、要有深度、要让老板满意。
```

问题：全是形容词，没有一句可执行。"有深度"是什么？AI 只能猜。

**样子二：像目录**

```
1. 收集数据
2. 分析数据
3. 输出报告
```

问题：这三步谁都会说，等于没说。要写清"收集哪些数据""怎么分析""报告分几段"。

**样子三：像法律条文**

```
本技能适用于所有涉及文本处理、信息整理、内容生成之场景……
```

问题：太抽象。AI 不需要这么正式的表述，它需要具体的例子和动作。

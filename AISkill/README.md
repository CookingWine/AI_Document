# AISkill 使用手册（零基础版）

> **这套文档写给谁**
> 没怎么用过 AI，也没写过代码的人。
>
> **你需要会什么**
> 会开文件夹、会打字、会复制粘贴，就够了。其他都在这里讲。
>
> **读完你能做到什么**
> 自己给 AI 写一份"工作手册"，让它每次都按你的要求稳定干活，而不是每次都要你从头交代一遍。

---

## 先读这个：用三句话认识这件事

**第一句**：现在的 AI 程序（比如各种聊天机器人）像一个刚入职的实习生——书读得多、脑子快，但完全不了解你的工作、你的习惯、你公司的规矩。

**第二句**：你要它把活干好，就得给它交代清楚。交代得越具体，它做得越对；交代得含糊，它就自由发挥。

**第三句**：AISkill 就是**把这份交代提前写好、存成一个文件**。以后每次要用，直接把这个文件递给它，不用再从头口述一遍。

下面的九篇正文，就是把这三句话拆开，一步步讲透，最后带你做出自己的第一份。

## 零基础速览（第一次来，先看这一节）

**这个文件夹是干什么的**

把"每次都要口头交代一遍"的做法，写成一份文件，让 AI 每次照着做。

**它解决什么问题**

同样的话说十遍；每次结果不一样；你的经验只在你一个人脑子里，别人拿不走。

**打个比方**

给新同事配一本岗位操作手册。他不用每次来问你，翻到第 3 页照着做就行；手册写得好不好，直接决定他做得对不对。

| 类别 | 文件 | 作用 |

一句话：这里管"这类活按什么标准做"，不管"边界"，也不管"派活"。

## 这套文档是怎么组织的

原来是"一本书"，现在拆成了"一个书柜"：按主题分成九篇正文，外加模板和变更记录。

这么拆有三个好处：

- **想查什么，直接翻那一篇。** 不用从头滚到尾。
- **改一处不影响别处。** 比如只改"常见问题"，不用碰"制作步骤"。
- **可以只发其中一篇给同事。** 比如他只想动手做，就把 `docs/04-制作步骤.md` 单独发给他。

## 文件之间的引用关系

各篇不是彼此独立的散篇，而是有明确的先后和依赖。理清这层关系，改的时候才不会漏。

```
                    ┌─────────────┐
                    │  README.md  │  总入口：导航 + 阅读路径
                    └──────┬──────┘
                           │ 指向全部
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
   ┌─────────┐       ┌──────────┐      ┌───────────┐
   │  01 概念 │──────▶│ 02 认识   │─────▶│ 03 适用场景│
   └────┬────┘       └────┬─────┘      └─────┬─────┘
        │                 │                   │
        └────────┬────────┴───────────────────┘
                 ▼
          ┌─────────────┐       引用     ┌──────────────┐
          │ 04 制作步骤  │───────────────▶│ templates/   │
          └──────┬──────┘                │ SKILL-模板    │
                 │                       │ 说明书-模板   │
                 ├──────────────┐        └──────────────┘
                 ▼              ▼
          ┌───────────┐   ┌──────────┐
          │05 使用方法 │   │06 质量检查│  ← 04 的验收标准
          └───────────┘   └──────────┘
                 │              │
                 └──────┬───────┘
                        ▼
                ┌───────────────┐
                │ 07 错误 08 问答│  遇到问题往回查
                └───────────────┘

   09 术语表：被以上所有文件引用，任何一处出现生词都指向它
   CHANGELOG：记录以上所有文件的每次变更
```

四条规则，记住就不会乱：

1. **`README.md` 是唯一入口。** 任何人不该"从中间某篇开始摸索"，入口永远先给这篇。
2. **正文单向前进。** 01 → 02 → 03 → 04 → 05 → 06 是学习顺序，倒着读会缺前提。
3. **`04` 依赖 `templates/`。** 第 4 步要照着模板填空，模板改了，04 里的说明要同步。
4. **`06` 是 `04` 的验收标准。** 写完必须回来对一遍清单，不是可选项。

每篇文件的开头都标了"读这篇之前"，结尾都标了"下一篇"，跟着走不会迷路。

## 维护约定

拆分之后，改文档要遵守几条规则，否则很快就会乱回去。

**改哪一篇**

| 你想改的内容 | 改哪个文件 |
| --- | --- |
| 新增一个概念的讲解 | `docs/01-基础概念.md` |
| 调整制作流程的某一步 | `docs/04-制作步骤.md`，并检查 `templates/` 是否要跟着改 |
| 补充一条新手易错点 | `docs/07-常见错误.md` |
| 回答了一个新问题 | `docs/08-常见问题.md` |
| 新增术语 | `docs/09-术语表.md`，并在首次出现的正文里加链接 |
| 模板填空项变了 | `templates/` 下对应文件，并同步 `04` 的说明 |

**四条硬规则**

1. **一篇只讲一件事。** 想加的内容放不进现有任何一篇，才新建文件，并更新本页索引。
2. **引用一律用相对路径。** 写 `../docs/09-术语表.md`，不写 `/Users/你/...`。
3. **改了内容就记一笔。** 在 [CHANGELOG](CHANGELOG.md) 加一行，写清"改了什么"，不写"更新"。
4. **术语只在一处定义。** 术语表是唯一权威，正文里用词要跟它一致；改词要同步改所有出现的地方。

**新增一篇的步骤**

1. 在 `docs/` 下按序号命名，比如 `10-团队协作.md`。
2. 复制任意一篇的文件头（所属、读前、读完、相关文件），改成自己的。
3. 在本页"文件索引"表里加一行。
4. 上一篇文章的结尾导航加一个"下一篇"。
5. 在 `CHANGELOG.md` 记一笔。

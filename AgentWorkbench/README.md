# AgentWorkbench 开发文档（C# + Avalonia）

> **这套文档写给谁**
> 准备用 C# 和 Avalonia 把"接入 AI Agent 的管理工具"真正写出来的人。
>
> **你需要会什么**
> 会 C#、能看懂 XAML、知道什么是 NuGet 包。AI 那部分不要求有经验，第 06、07 篇从零讲。
>
> **读完你能做到什么**
> 在 8 个工作日内交出一个能演示、能验收的 Demo：打开表格、载入新版本做对比、用一句话让模型改数据，改动先给你看、你点头才生效、随时能撤回。

---

## 先读这个：三句话

**第一句**：这个产品不是"给表格配一个聊天框"，而是**给 AI 装一条受控的变更管线**。模型能读、能提议，但能不能落到数据上，由你按一下按钮决定。

**第二句**：Demo 的价值不在功能多，在于**闭环完整**——导入、对比、对话、提议、确认、应用、撤回、留痕，八步全部跑通一遍，比做十个半截功能有用。

**第三句**：先做确定的部分（数据模型、差异计算、界面骨架），再接不确定的部分（大模型）。反过来做，你会花三天调提示词，却发现连"哪些行变了"都算不准。

## 阶段总览

按里程碑推进，每个都能独立验收。天数按一个人、熟悉 C#、不熟悉 Avalonia 估算。

| 里程碑 | 目标 | 主要产出 | 验收一句话 | 预估 |
| --- | --- | --- | --- | --- |
| M0 | 环境与骨架跑起来 | 空窗口 + 分层解决方案 | `dotnet run` 出窗口，五个项目依赖正确 | 0.5 天 |
| M1 | 数据能进能出能显示 | 文档模型、CSV 读写、表格网格 | 打开 40 行 CSV，改动后能存回 JSON | 1 天 |
| M2 | 两个版本能对比 | 差异引擎、变更列表、高亮 | 导入 v2，准确报出 6 改 2 增 1 删 | 1 天 |
| M3 | 模型能读表 | Provider 配置、只读工具、对话面板 | 问"研发部有几个人"，答对且给出依据行 | 1.5 天 |
| M4 | 模型能改表（需确认） | 提议工具、校验器、确认门 | 说"给张三涨 10%"，出预览，点确认才生效 | 1.5 天 |
| M5 | 能审、能撤、能查 | 逐条审阅、撤销栈、审计日志 | 拒绝一条只应用其余；撤销回到原值 | 1 天 |
| M6 | 能交付 | 打包、演示脚本、验收记录 | 换台机器解压即跑，三条脚本全过 | 1 天 |

合计约 7.5 人日。M2 是关键路径，M3/M4 的不确定性最大，不要把 M2 的时间挪给 M4。

## Demo 边界一览

完整表在 [09](./docs/09-Demo实施计划.md#92-功能边界)，这里只记结论。

**必须做（P0）**：单表文档、CSV 导入导出、版本对比与高亮、只读问答、自然语言改动、变更预览与确认、逐条接受/拒绝、撤销、审计日志、无 Key 也能演示的 Mock 模式。

**可以做（P1，有余力再说）**：XLSX 导入、diff 报告导出 Markdown、多轮修正、列级规则配置界面。

**明确不做**：多表关联、公式计算、图表透视、多人协作与云同步、账号体系、任意脚本执行、插件市场、Excel 样式保真、超过 5000 行的性能承诺。

砍需求时按这个顺序砍：P1 全砍 → 撤销栈退化为单步 → 审计日志只记文件 → **确认门不能砍**。确认门一砍，这个 Demo 就没有演示价值了。

## 交付物（输出要求）

M6 结束时，目录里应该有这些东西，缺一样都算没交付：

```
AgentWorkbench/
├── src/
│   ├── AgentWorkbench.App/            可运行界面
│   ├── AgentWorkbench.Core/           领域模型、差异、补丁
│   ├── AgentWorkbench.Agents/         Agent 循环与工具
│   └── AgentWorkbench.Infrastructure/ 文件、配置、日志
├── tests/
│   ├── AgentWorkbench.Core.Tests/     差异与校验单测
│   └── AgentWorkbench.Agents.Tests/   循环与工具测试
├── samples/
│   ├── employees.v1.csv               40 行基线数据
│   ├── employees.v2.csv               6 改 2 增 1 删
│   └── rules.json                     受保护列与值域规则
├── docs/
│   ├── demo-script.md                 三段演示台词与预期
│   └── acceptance.md                  12 条验收记录（含截图）
└── artifacts/
    ├── diff-report.md                 导出的对比报告样例
    └── audit-2026-11-05.jsonl         审计日志样例
```

四条硬指标：

1. **一条命令启动**：`dotnet run --project src/AgentWorkbench.App`，不需要改代码、不需要手动放文件。
2. **无 Key 可演示**：没配 API Key 时自动进 Mock 模式，三段脚本照样跑完，界面上明确显示"MOCK"。
3. **改错能退**：任何一次应用都能一键撤销，撤销后文档内容与操作前逐单元格一致。
4. **留痕可查**：每次模型调用、每次工具调用、每次确认，都在 `artifacts/` 的 JSONL 里有一行。

## 维护约定

1. **文档跟着里程碑走。** 每个里程碑结束时，回来改对应那篇里"实际做法"的段落，别让它停在计划状态。
2. **一篇只讲一件事。** 想加的内容塞不进任何一篇，才新建，并更新本页索引。
3. **引用一律相对路径。** 写 `../AIAgents/README.md`，不写本机绝对路径。
4. **版本号写实际用到的。** 文中标的 Avalonia 12.1.x、.NET 10、Microsoft.Extensions.AI 10.x 是 2026 年 10 月的稳定版；升级了就改文中的数字，别让文档和 csproj 对不上。
5. **代码片段是骨架不是成品。** 每段都标了所在文件，落地时以能编译为准；编译不过先查版本，再查命名空间。

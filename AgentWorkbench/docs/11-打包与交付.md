## 11.1 三种运行方式，各用在哪

| 方式 | 命令 | 体积 | 用在哪 |
| --- | --- | --- | --- |
| 源码运行 | `dotnet run --project src/AgentWorkbench.App` | — | 自己开发 |
| 框架依赖 | `dotnet publish -c Release` | 约 15 MB | 对方装了 .NET 10 运行时 |
| 自包含 | 加 `-r <rid> --self-contained true` | 约 90–110 MB | **交付给没装 .NET 的人，选这个** |

Demo 交付一律用自包含。多 80 MB 换来"双击就能开"，比让对方先装运行时划算得多——尤其是演示前十分钟。

## 11.2 发布命令

macOS（Apple Silicon，你的开发机）：

```bash
dotnet publish src/AgentWorkbench.App -c Release -r osx-arm64 \
  --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true \
  -o dist/osx-arm64
```

Windows（在 macOS 上可以交叉发布，签名另说）：

```bash
dotnet publish src/AgentWorkbench.App -c Release -r win-x64 \
  --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true \
  -o dist/win-x64
```

四条参数的作用：

| 参数 | 作用 | 不加会怎样 |
| --- | --- | --- |
| `-r osx-arm64` / `-r win-x64` | 指定运行时标识 | 打出来是框架依赖包 |
| `--self-contained true` | 把运行时打进包 | 对方需要装 .NET |
| `PublishSingleFile` | 合成一个可执行文件 | 输出几十个 dll，看起来像半成品 |
| `IncludeNativeLibrariesForSelfExtract` | 把原生库（SkiaSharp 等）也塞进去 | 运行时报找不到 `libSkiaSharp` |
| `EnableCompressionInSingleFile` | 压缩，体积减 30–40% | 包大，但启动略快 |

**不要开 `PublishTrimmed=true`。** 裁剪会删掉 XAML 反射用到的类型，表现为"编译通过、运行白屏"，而且报错信息毫无指向性。Demo 不缺那 20 MB。

## 11.3 macOS 上会被拦，先处理

未签名的可执行文件从网上下载后，macOS 会加一个隔离属性，双击提示"无法打开，因为 Apple 无法验证"。

三个层次的处理，按投入排：

**第一层：什么都不做，教对方右键打开。**
右键 → 打开 → 再点"打开"。一次之后就不再提示。适合内部演示。

**第二层：去掉隔离属性（推荐给 Demo）。**
交付时附一行命令，或者写进 `启动.command`：

```bash
xattr -dr com.apple.quarantine "$(dirname "$0")/AgentWorkbench"
```

**第三层：正式签名 + 公证。**
需要 Apple Developer 账号（每年 99 美元）：

```bash
codesign --force --deep --options runtime \
  --sign "Developer ID Application: Your Name (TEAMID)" dist/osx-arm64/AgentWorkbench

xcrun notarytool submit AgentWorkbench.zip \
  --apple-id you@example.com --team-id TEAMID --password app-specific-password --wait

xcrun stapler staple dist/osx-arm64/AgentWorkbench
```

Demo 阶段做到第二层就够。第 12 篇把这个列为产品化必须补的一项。

**临时签名**只解决"本机运行"的问题，不解决分发：

```bash
codesign --force --deep --sign - dist/osx-arm64/AgentWorkbench
```

## 11.4 交付包长什么样

macOS 版（文件夹，不强行做 `.app`）：

```
AgentWorkbench-demo-macos-arm64/
├── 启动.command              ← 双击启动，内含去隔离 + 运行
├── AgentWorkbench            ← 单文件可执行
├── appsettings.json          ← 出厂配置，Key 留空
├── README.txt                ← 三行说明：怎么跑、怎么配 Key、已知限制
├── samples/
│   ├── employees.v1.csv
│   ├── employees.v2.csv
│   └── rules.json
├── docs/
│   ├── demo-script.md
│   └── acceptance.md
└── artifacts/                ← 预置一份示例报告与日志，便于讲解
```

`启动.command` 内容（**必须 `chmod +x`**，否则双击没反应）：

```bash
#!/bin/bash
cd "$(dirname "$0")"
xattr -dr com.apple.quarantine ./AgentWorkbench 2>/dev/null
./AgentWorkbench
```

Windows 版同理，把 `启动.command` 换成 `启动.bat`：

```bat
@echo off
cd /d "%~dp0"
start "" AgentWorkbench.exe
```

**为什么不做 `.app` 包。** 做一个能用的 `.app` 需要手写 `Info.plist`、摆 `Contents/MacOS` 结构、处理图标与 Dock 名称，大约半天，而且 `dotnet publish` 不会帮你做。Demo 用文件夹 + 启动脚本，五十行都不用，效果一样。要做也是 M7 的事。

## 11.5 首次运行

配置查找顺序（[03](./03-工程骨架与约定.md) 3.4 已定），交付时要保证前两步不炸：

1. 程序目录下的 `appsettings.json` —— 出厂配置，`Agent.ApiKey` 留空。
2. 用户目录 `~/Library/Application Support/AgentWorkbench/appsettings.json` —— 首次运行可以不存在。
3. 环境变量 `AGENTWORKBENCH_AGENT__APIKEY` —— 有就用。

三种情况的表现：

| 情况 | 期望表现 |
| --- | --- |
| 什么都没配 | 正常启动，顶部横幅"未配置密钥，当前为 MOCK 演示模式" |
| 只有出厂配置 | 同上（因为 Key 为空） |
| 配了环境变量 | 状态栏显示模型名，无 MOCK 标记 |

**首次运行自动做的事**：创建用户配置目录（失败不阻塞启动，只记日志）、创建 `artifacts/` 目录。不要创建任何"示例文档"到用户桌面——那是最招人烦的行为之一。

## 11.6 版本号与变更记录

`0.1.0-demo.1` 这种格式：`主.次.修订-阶段.序号`。

| 变化 | 怎么加 |
| --- | --- |
| 加功能 | 次 +1 |
| 修 bug | 修订 +1 |
| 重新打包但代码没变（换图标、改配置） | 阶段序号 +1 |

版本号写在 `AgentWorkbench.App.csproj` 的 `<Version>`，启动时显示在标题栏或"关于"。发布前打 tag：

```bash
git tag -a v0.1.0-demo.1 -m "Demo 首个可演示版本"
git push origin v0.1.0-demo.1
```

变更记录只写"改了什么、为什么"，不写"优化了体验"这种话。三五行就够，格式：

```
## 0.1.0-demo.2
- 修复：撤销后再导入新版本，版本号回退到旧值
- 调整：审阅栏默认全选，减少演示时的点击
```

## 11.7 交付前检查清单

在**另一台机器**上做，不要在自己机器上测。

- [ ] 解压后双击能启动，不需要命令行
- [ ] 打开 `samples/employees.v1.csv` 正常显示 40 行
- [ ] 导入 v2，对比计数正确
- [ ] 未配 Key 时显示 `MOCK` 横幅，三段脚本仍能跑
- [ ] 配好 Key 后真实模型可对话
- [ ] 改数据 → 确认 → 撤销，全链路正常
- [ ] `artifacts/` 目录被自动创建，日志有内容
- [ ] 关窗口不弹异常对话框
- [ ] 程序目录里没有 `.pdb`、没有 `obj/`、没有测试数据残留
- [ ] 包体积在预期范围（macOS 约 60–80 MB，Windows 约 70–90 MB）
- [ ] `README.txt` 里的三条说明与实际行为一致
- [ ] `docs/demo-script.md` 里的台词，照着念一遍能走通

最后一条最容易被跳过，也最容易翻车：脚本里写的"点这里"，界面改版之后那个按钮已经不在了。

---

## 本篇要点

- 交付用自包含单文件，`PublishTrimmed` 必须为 `false`。
- macOS 一定要处理隔离属性，`xattr -dr com.apple.quarantine` 写进启动脚本。
- 不做 `.app` 包，文件夹 + `启动.command` 就够，省半天。
- 出厂配置里 Key 留空，缺 Key 时进 MOCK 并明确提示，这是正常状态不是错误。
- 交付前必须在另一台机器上照脚本走一遍，重点验"双击能开"和"没 Key 能演示"。

## 3.1 建项目（约 15 分钟）

```bash
cd ~/Desktop/Demo/AI_Document/AgentWorkbench

# 三个类库
dotnet new classlib -o src/AgentWorkbench.Core           -n AgentWorkbench.Core
dotnet new classlib -o src/AgentWorkbench.Agents         -n AgentWorkbench.Agents
dotnet new classlib -o src/AgentWorkbench.Infrastructure -n AgentWorkbench.Infrastructure

# 两个测试项目
dotnet new xunit -o tests/AgentWorkbench.Core.Tests   -n AgentWorkbench.Core.Tests
dotnet new xunit -o tests/AgentWorkbench.Agents.Tests -n AgentWorkbench.Agents.Tests

# 全部挂到解决方案
dotnet sln add src/AgentWorkbench.Core src/AgentWorkbench.Agents \
  src/AgentWorkbench.Infrastructure src/AgentWorkbench.App \
  tests/AgentWorkbench.Core.Tests tests/AgentWorkbench.Agents.Tests

# 依赖方向（只允许这五条 + 两条测试引用）
dotnet add src/AgentWorkbench.Agents reference src/AgentWorkbench.Core
dotnet add src/AgentWorkbench.Infrastructure reference src/AgentWorkbench.Core
dotnet add src/AgentWorkbench.App reference src/AgentWorkbench.Core src/AgentWorkbench.Agents src/AgentWorkbench.Infrastructure
dotnet add tests/AgentWorkbench.Core.Tests reference src/AgentWorkbench.Core
dotnet add tests/AgentWorkbench.Agents.Tests reference src/AgentWorkbench.Agents src/AgentWorkbench.Core

# 删掉模板生成的 Class1.cs
rm src/*/Class1.cs tests/*/UnitTest1.cs 2>/dev/null
```

建完立刻做一次"依赖体检"：`dotnet list src/AgentWorkbench.Core reference` 必须是空的。Core 一旦引了别的东西，第 2.2 节的三条规矩就破了。

## 3.2 集中管理版本

两个 `Directory.Build.props` 级别的文件放在 `AgentWorkbench/` 根目录，所有项目共享。

**`Directory.Build.props`** —— 统一编译选项，省得每个 csproj 抄一遍：

```xml
<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <InvariantGlobalization>false</InvariantGlobalization>
  </PropertyGroup>
</Project>
```

`InvariantGlobalization` 必须是 `false`：表格里有中文，日期解析要用到区域信息，开了 invariant 模式会踩坑。

**`Directory.Packages.props`** —— 版本只写一次，升级只改一处：

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
    <AvaloniaVersion>12.1.4</AvaloniaVersion>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Avalonia" Version="$(AvaloniaVersion)" />
    <PackageVersion Include="Avalonia.Desktop" Version="$(AvaloniaVersion)" />
    <PackageVersion Include="Avalonia.Themes.Fluent" Version="$(AvaloniaVersion)" />
    <PackageVersion Include="Avalonia.Fonts.Inter" Version="$(AvaloniaVersion)" />
    <PackageVersion Include="Avalonia.Controls.DataGrid" Version="$(AvaloniaVersion)" />
    <PackageVersion Include="CommunityToolkit.Mvvm" Version="8.4.0" />
    <PackageVersion Include="Microsoft.Extensions.Hosting" Version="10.0.0" />
    <PackageVersion Include="Microsoft.Extensions.AI" Version="10.11.0" />
    <PackageVersion Include="Microsoft.Extensions.AI.OpenAI" Version="10.11.0" />
    <PackageVersion Include="xunit" Version="2.9.2" />
    <PackageVersion Include="Microsoft.NET.Test.Sdk" Version="17.12.0" />
  </ItemGroup>
</Project>
```

项目里只写 `<PackageReference Include="Avalonia" />`，不带 `Version`。版本号集中在这里，第 01 篇 1.4 的表才有意义。

> 实际版本以 `dotnet list package --outdated` 的结果为准。写死是为了复现，不是为了追新。

**`src/AgentWorkbench.App/AgentWorkbench.App.csproj`** 关键几行：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <BuiltInComInteropSupport>true</BuiltInComInteropSupport>
    <ApplicationManifest>app.manifest</ApplicationManifest>
    <AvaloniaUseCompiledBindingsByDefault>true</AvaloniaUseCompiledBindingsByDefault>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Avalonia" />
    <PackageReference Include="Avalonia.Desktop" />
    <PackageReference Include="Avalonia.Themes.Fluent" />
    <PackageReference Include="Avalonia.Fonts.Inter" />
    <PackageReference Include="Avalonia.Controls.DataGrid" />
    <PackageReference Include="CommunityToolkit.Mvvm" />
    <PackageReference Include="Microsoft.Extensions.Hosting" />
    <PackageReference Include="Microsoft.Extensions.AI" />
  </ItemGroup>
</Project>
```

`AvaloniaUseCompiledBindingsByDefault=true` 意味着 XAML 里**必须**写 `x:DataType`，否则编译报错。这是好事：绑定写错在编译期就发现，不用运行时盯着空白界面猜。

## 3.3 启动与依赖注入

三个文件，各管一段。

**`src/AgentWorkbench.App/Program.cs`**

```csharp
using Avalonia;

namespace AgentWorkbench.App;

internal static class Program
{
    [STAThread]
    public static void Main(string[] args) =>
        BuildAvaloniaApp().StartWithClassicDesktopLifetime(args);

    public static AppBuilder BuildAvaloniaApp() =>
        AppBuilder.Configure<App>()
            .UsePlatformDetect()
            .WithInterFont()
            .LogToTrace();
}
```

**`src/AgentWorkbench.App/App.axaml.cs`** —— 在这里把容器建起来，窗口从容器里拿：

```csharp
using Avalonia;
using Avalonia.Controls.ApplicationLifetimes;
using Avalonia.Markup.Xaml;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using AgentWorkbench.App.ViewModels;
using AgentWorkbench.App.Views;

namespace AgentWorkbench.App;

public partial class App : Application
{
    private IHost? _host;

    public override void Initialize() => AvaloniaXamlLoader.Load(this);

    public override void OnFrameworkInitializationCompleted()
    {
        if (ApplicationLifetime is IClassicDesktopStyleApplicationLifetime desktop)
        {
            var builder = Host.CreateApplicationBuilder();
            ConfigureServices(builder);
            _host = builder.Build();

            desktop.MainWindow = _host.Services.GetRequiredService<MainWindow>();
            desktop.Exit += (_, _) => _host?.Dispose();
        }

        base.OnFrameworkInitializationCompleted();
    }

    private static void ConfigureServices(HostApplicationBuilder builder)
    {
        builder.Services.AddSingleton<ShellViewModel>();
        builder.Services.AddSingleton<MainWindow>();
        // 领域与基础设施在 M1/M3 逐个补进来
    }
}
```

**`MainWindow.axaml.cs`** 只做一件事——把 DataContext 设上：

```csharp
public partial class MainWindow : Window
{
    public MainWindow(ShellViewModel vm)
    {
        InitializeComponent();
        DataContext = vm;
    }
}
```

DI 里注册的三条约定，照做就不会乱：

1. **无状态服务用 `Singleton`**（差异引擎、校验器、配置）。**带用户状态的用 `Transient`**（一次会话的 ViewModel）。
2. **不在 ViewModel 里 `new` 服务**，全部构造函数注入。写测试时替换成假实现，一行搞定。
3. **窗口只注册一次**。每次 `GetRequiredService<MainWindow>()` 拿同一个实例，避免多窗口共享 ViewModel 时状态错乱。

## 3.4 配置与密钥

三层，后面的覆盖前面的：

| 层 | 位置 | 放什么 | 进 Git 吗 |
| --- | --- | --- | --- |
| 默认值 | 代码里的 `AgentOptions` | 模型名、超时、轮次上限 | 是 |
| 出厂配置 | `appsettings.json`（随程序发布） | Provider、BaseUrl、温度 | 是 |
| 用户配置 | `~/Library/Application Support/AgentWorkbench/appsettings.json`（Windows 为 `%APPDATA%`） | 用户自己的模型与偏好 | 否 |
| 环境变量 | `AGENTWORKBENCH_API_KEY` 等 | 密钥 | 否 |

**密钥优先级**：环境变量 > 用户配置文件 > 没有（进 Mock 模式）。**任何时候都不写进 `appsettings.json`，不写进日志，不进异常消息。**

**`src/AgentWorkbench.Infrastructure/Configuration/AgentOptions.cs`**

```csharp
public sealed class AgentOptions
{
    public string Provider { get; set; } = "openai-compatible";
    public string BaseUrl { get; set; } = "https://api.openai.com/v1";
    public string Model { get; set; } = "gpt-4.1-mini";
    public string? ApiKey { get; set; }
    public int MaxTurns { get; set; } = 8;
    public int MaxOutputTokens { get; set; } = 2000;
    public double Temperature { get; set; } = 0.0;

    public bool IsConfigured =>
        !string.IsNullOrWhiteSpace(ApiKey) && !string.IsNullOrWhiteSpace(Model);
}
```

温度固定 0：改数据这件事不需要"创意"，需要可复现。

**加载顺序**（写在 `App.axaml.cs` 的 `ConfigureServices` 里）：

```csharp
var userConfig = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
    "AgentWorkbench", "appsettings.json");

builder.Configuration
    .AddJsonFile(Path.Combine(AppContext.BaseDirectory, "appsettings.json"), optional: true)
    .AddJsonFile(userConfig, optional: true)
    .AddEnvironmentVariables("AGENTWORKBENCH_");

builder.Services.Configure<AgentOptions>(builder.Configuration.GetSection("Agent"));
```

环境变量加前缀之后，`AGENTWORKBENCH_AGENT__APIKEY` 会映射到 `Agent:ApiKey`。演示时现场 `export` 一下就切换 Key，不用改文件。

## 3.5 日志：两份，别混

| 日志 | 给谁看 | 位置 | 内容 |
| --- | --- | --- | --- |
| 运行日志 | 开发排查 | `~/Library/Logs/AgentWorkbench/app.log` | 异常、启动参数、耗时 |
| 审计日志 | 用户与验收 | `artifacts/audit-<日期>.jsonl` | 每次模型调用、工具调用、确认结果（见 07.7） |

运行日志用 `Microsoft.Extensions.Logging`，写一个 30 行的文件 Provider 就够，不必引 Serilog：

```csharp
public sealed class FileLoggerProvider(string path) : ILoggerProvider
{
    private readonly object _gate = new();
    private readonly StreamWriter _writer = new(path, append: true) { AutoFlush = true };

    public ILogger CreateLogger(string categoryName) => new FileLogger(this, categoryName);

    public void Dispose() => _writer.Dispose();

    private sealed class FileLogger(FileLoggerProvider owner, string category) : ILogger
    {
        public IDisposable? BeginScope<TState>(TState state) where TState : notnull => null;
        public bool IsEnabled(LogLevel level) => level >= LogLevel.Information;

        public void Log<TState>(LogLevel level, EventId id, TState state, Exception? ex,
            Func<TState, Exception?, string> formatter)
        {
            if (!IsEnabled(level)) return;
            var line = $"{DateTimeOffset.Now:O} [{level}] {category} {formatter(state, ex)}";
            lock (owner._gate) owner._writer.WriteLine(line);
        }
    }
}
```

审计日志**不要**用这个 Provider。它是结构化数据，需要机器可读、需要能按会话过滤，单独写（07.7）。

## 3.6 命名与代码约定

| 场景 | 约定 | 例子 |
| --- | --- | --- |
| 异步方法 | `Async` 后缀，必带 `CancellationToken` | `Task<TableDocument> LoadAsync(string path, CancellationToken ct)` |
| 领域模型 | `sealed record`，不可变 | `public sealed record Row(string Id, ...)` |
| 可变状态 | 只在 ViewModel 里，`ObservableObject` | `[ObservableProperty] private string _status;` |
| 接口 | `I` 前缀，动词开头表能力 | `IDocumentStore`、`IAuditLog` |
| 工具方法名 | 蛇形，给模型看的 | `get_table_schema`、`propose_changes` |
| 私有字段 | `_camelCase` | `_diffEngine` |
| 常量 | PascalCase | `MaxOpsPerProposal` |
| 命名空间 | 与目录一致，分层 | `AgentWorkbench.Core.Diff` |

四条纪律：

1. **`Nullable` 全开，不留 `!`。** 出现 `!` 说明设计有问题，先想清楚"这里为什么可能为空"。
2. **`TreatWarningsAsErrors=true`。** 警告当错误，省得攒到最后一堆。
3. **Core 里不出现 `Console.WriteLine`、`MessageBox`、`DateTime.Now`。** 时间通过 `TimeProvider` 注入，否则测试不可复现。
4. **一个文件一个公开类型。** 除了小的 record 组合（如 `ChangeSet` 里的子类型），别堆。

## 3.7 Git 约定

分支：`main` 保持可运行，功能分支 `feat/m1-data-model`、`fix/diff-null-handling`。

提交信息：`type(scope): 摘要`，与仓库现有习惯一致。

```
feat(core): 新增差异引擎与行列变更模型
fix(diff): 修正空值与空字符串被判为相同的问题
test(core): 补充无主键场景的配对用例
docs(arch): 补充决策三的理由
chore(deps): Avalonia 升级至 12.1.4
```

`.gitignore` 至少要盖住这些——漏一个就可能把密钥或几十兆的 bin 提交上去：

```
bin/
obj/
.vs/
.idea/
*.user
artifacts/*.jsonl
artifacts/screenshots/
samples/*.local.json
appsettings.*.local.json
```

`samples/` 里的示例数据要提交；`artifacts/` 里只提交那份 diff 报告样例，运行产生的日志和截图不进仓库。

## 3.8 骨架自检

M0 结束前逐条打勾：

- [ ] `dotnet build` 零错误零警告
- [ ] `dotnet run --project src/AgentWorkbench.App` 出窗口
- [ ] `dotnet list src/AgentWorkbench.Core reference` 输出为空
- [ ] `dotnet test` 能跑（两个空测试项目，0 通过 0 失败也算）
- [ ] `git status` 干净，`bin/`、`obj/` 没被跟踪
- [ ] 配置文件三层加载验证过：改用户配置文件里的 `Model`，界面上能显示出来
- [ ] 故意删掉 `appsettings.json`，程序仍能启动（`optional: true` 生效）

## 本篇要点

- 五个项目的依赖用 `dotnet add reference` 一次接好，然后立刻验证 Core 是零依赖。
- 版本集中在 `Directory.Packages.props`，编译选项集中在 `Directory.Build.props`。
- DI 在 `App.axaml.cs` 建，窗口从容器取，ViewModel 全部构造函数注入。
- 配置三层覆盖，密钥只走环境变量或用户目录，永不入 Git、不入日志。
- 运行日志与审计日志是两份东西，别混在一起写。

## 1.1 先回答三个问题，再动手

写代码之前，把这三句话写进 `docs/demo-script.md` 的第一屏。写不出来，说明还没想清楚，先别建项目。

| 问题 | 这个 Demo 的答案 |
| --- | --- |
| 做给谁看 | 想看"AI 能不能安全地改业务数据"的同事或客户，不是终端用户 |
| 看完要记住什么 | 模型改了哪几格、为什么改、我点过头它才生效、点错了能退 |
| 什么算成功 | 三段演示脚本一次跑完，不崩、不卡、不需要人工救场 |

三个答案对应三个设计约束：**可读的差异**、**可见的确认**、**可逆的操作**。后面所有技术选择都服从这三条。

## 1.2 第一天只做四步

不要在这一天接模型。目标只有一个：屏幕上出现一个窗口，里面有一张假的表。

```bash
# 第 1 步：装 .NET 10 SDK（macOS，Apple Silicon）
brew install --cask dotnet-sdk
# 或者用官方脚本：curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0

dotnet --version          # 期望 10.0.x
```

```bash
# 第 2 步：装 Avalonia 模板
dotnet new install Avalonia.Templates

# 第 3 步：建解决方案与界面项目
mkdir -p ~/Desktop/Demo/AI_Document/AgentWorkbench/src
cd ~/Desktop/Demo/AI_Document/AgentWorkbench
dotnet new sln -n AgentWorkbench
dotnet new avalonia.mvvm -o src/AgentWorkbench.App -n AgentWorkbench.App
dotnet sln add src/AgentWorkbench.App
```

```bash
# 第 4 步：跑起来
dotnet run --project src/AgentWorkbench.App
```

出现一个空白窗口，这一步就结束了。窗口标题改成 `AgentWorkbench`，关掉，收工。

**如果第 4 步失败**，按这个顺序查，八成是前两个原因：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `dotnet: command not found` | PATH 没生效 | 重开终端；或 `export PATH="$HOME/.dotnet:$PATH"` |
| `NETSDK1045 当前 SDK 不支持 net10.0` | SDK 版本旧 | `dotnet --list-sdks` 看有没有 10.x，没有就重装 |
| `Unable to load shared library libSkiaSharp` | 架构不匹配（x64 装在 arm64） | 卸载后装 arm64 包，`uname -m` 应为 `arm64` |
| 窗口起来但一片空白 | 模板的 `MainWindow` 没设 `DataContext` | 检查 `App.axaml.cs` 里是否注册了 `MainWindow` |

## 1.3 为什么是这个顺序

只有一条理由：**先做能验证的部分，后做要靠运气的部分。**

差异计算对不对，跑两个文件就知道；界面卡不卡，点两下就知道。模型听不听话，你只能一次次试，而且换了模型、换了提示词，昨天的结论就作废。所以模型必须放在最后，等前面有了一张"正确答案"的表，它改得对不对才有对照物。

反过来做会发生什么，很具体：你第二天就接了模型，第三天开始调提示词，第五天发现"给张三涨薪"改错了行——因为行没有稳定标识，模型说的"张三"和你以为的"张三"不是同一行。于是回头重做数据层，提示词白调。

## 1.4 环境与版本

2026 年 10 月的稳定组合。装完对一遍，数字不一致就以你机器上能跑通的为准，并同步改本表。

| 组件 | 版本 | 用途 | 备注 |
| --- | --- | --- | --- |
| .NET SDK | 10.0.x（LTS） | 运行时与编译 | Avalonia 12 同时支持 net8.0/net10.0，新项目直接 10 |
| Avalonia | 12.1.x | UI 框架 | 12.0 起渲染重写，11.x 项目不要照抄本文 |
| Avalonia.Templates | 最新 | `dotnet new` 模板 | `dotnet new list avalonia` 可查 |
| CommunityToolkit.Mvvm | 8.4.x | `[ObservableProperty]`、`[RelayCommand]` | 源生成器，编译期产出 |
| Microsoft.Extensions.AI | 10.x | `IChatClient` 抽象 | 10.9 起有路由/故障转移，Demo 用不到 |
| Microsoft.Extensions.Hosting | 10.x | DI 与配置 | 桌面端也值得用，别手搓容器 |
| xUnit | 2.9.x | 单测 | Core 与 Agents 各一个测试项目 |
| Avalonia.Controls.DataGrid | 12.1.x | 表格控件 | 需在 `App.axaml` 引入主题样式 |
| ClosedXML（可选） | 0.10x | XLSX 读写 | 只在做 P1 的 XLSX 导入时引 |

关于 DataGrid 有两件事要先知道：

1. 它在官方定位里属于**维护模式**。Avalonia 12.1 新增了只读的 `TableView`，但可编辑表格仍以 DataGrid 为主。Demo 的编辑入口是对话，不是双击单元格，所以 DataGrid 够用。
2. 不引主题样式会显示成一堆没有边框的文字。`App.axaml` 的 `<Application.Styles>` 里要加：

```xml
<StyleInclude Source="avares://Avalonia.Controls.DataGrid/Themes/Fluent.xaml" />
```

## 1.5 三十分钟验收

做完 1.2，再花二十分钟加一个假表格，验证工具链是通的：

1. 在 `MainWindow.axaml` 放一个 `DataGrid`，`ItemsSource` 绑到 ViewModel 里的 `ObservableCollection<RowVm>`。
2. `RowVm` 就三个属性：工号、姓名、部门。
3. 构造函数里塞三行假数据。
4. 跑起来能看到三行、能滚动、改窗口大小列宽跟着变。

看到这四件事，M0 就完成了：

- [ ] `dotnet run` 直接出窗口，不需要先 build
- [ ] 表格有边框、有表头、能选中行
- [ ] 改 XAML 后重新运行能看到变化（Hot Reload 在 macOS 上时好时坏，别依赖）
- [ ] `dotnet build` 零警告

## 1.6 三个开局错误

**错误一：先做通用表格编辑器。**
"既然要做表格工具，先把增删改查、排序筛选、复制粘贴做全"——这是三周的量，而且和 AI 一点关系没有。Demo 的表格只需要**看得清、能高亮**，编辑一律走对话。

**错误二：先设计插件系统。**
想到"以后要接很多 Agent、很多模型"，于是先抽象一层插件协议。结果抽象出来的接口和第一个真实需求对不上，还得改。等第二个 Agent 真的出现再抽象，那时你才知道该抽象什么。

**错误三：把密钥写进代码。**
`new OpenAIClient("sk-...")` 提交上去，仓库就废了。从第一天起就只有两条路：环境变量，或用户目录下的配置文件（且 `.gitignore` 掉）。第 03 篇 3.4 有现成写法。

---

## 本篇要点

- 第一天只做四步：装 SDK、装模板、建项目、跑出窗口。**不要接模型。**
- 顺序的理由只有一条：先做能验证的（数据、差异、界面），后做要靠运气的（模型）。
- 版本以 .NET 10 + Avalonia 12.1 为基线，11.x 的教程不能照抄。
- DataGrid 要手动引主题样式，否则表格没有边框。
- 三个开局错误：先做通用编辑器、先设计插件系统、把密钥写进代码。

## 8.1 布局：三区一栏

界面只服务一件事：**让人在同一个视野里看完"模型想干什么"和"数据会变成什么样"。** 所以表格和对话必须并排，不能切页签。

```
╔═ 顶栏 ═══════════════════════════════════════════════════
║ 打开 · 导入新版本 · 保存 · 导出报告        员工花名册 v3
║
╠═ 主区 ═══════════════════════════════════════════════════
║
║  ┌ 左：表格（约 62%）────────────┐ ┌ 右：对话（约 38%）──┐
║  │ 工号   姓名   部门    月薪      │ │ 用户：研发部涨 5%    │
║  │ E1001  张伟   研发   24000     │ │                     │
║  │ E1003  李娜   研发   18000 ←改 │ │ 助手：将修改 6 行…   │
║  │ E1007  王强   平台   21000 ←改 │ │  ▸ 调用了 query_rows │
║  │ …                              │ │                     │
║  └────────────────────────────────┘ │ [输入框]      [发送] │
║                                     └─────────────────────┘
║
╠═ 审阅栏（有待确认时出现，否则收起）══════════════════════════
║ 待确认 p-003：修改 6 行 共 6 处    [全部接受] [全部拒绝]
║ ☑ 月薪 18000 → 18900（E1003）  ☑ 月薪 21000 → 22050（E1007）…
║
╠═ 状态栏 ═════════════════════════════════════════════════
║ MOCK · 本轮 2,410 tokens · 1.2s · 就绪
```

三条布局原则：

1. **审阅栏在下方、横跨全宽。** 放右侧会挤压对话，放弹窗会遮住表格——而用户恰恰要对着表格看变更。
2. **对话区固定宽度、可折叠。** 演示时不希望它抢戏，可以一键收起成 48px 竖条。
3. **状态栏常驻模型信息。** `MOCK` 标记必须在状态栏，不能只在设置里。

比例用 `Grid` 的星号列：左 `62*`、右 `38*`，中间 `GridSplitter` 可拖动，最小宽度各 320px。

## 8.2 ViewModel 分工

五个 ViewModel，各自只管一段，互相通过 Shell 协调，不要互相 `new`。

| ViewModel | 管什么 | 关键成员 | 不该管什么 |
| --- | --- | --- | --- |
| `ShellViewModel` | 组装、命令、跨区协调 | `Document`、`Table`、`Chat`、`Review`、`Status`、`OpenCommand`、`ImportVersionCommand`、`UndoCommand` | 具体算法 |
| `TableViewModel` | 列与行的显示模型 | `Columns`、`Rows`、`SelectedRow`、`Reload(document)` | 差异计算 |
| `RowViewModel` | 一行 | `RowId`、`Cells`（按列序）、`State` | 业务校验 |
| `CellViewModel` | 一格 | `Display`、`Before`、`State`、`Background` | 格式化规则（用 Converter） |
| `ChatViewModel` | 消息与输入 | `Messages`、`Input`、`SendCommand`、`CancelCommand`、`IsBusy` | 调模型（交给服务） |
| `ReviewViewModel` | 待确认变更 | `Items`、`AcceptSelectedCommand`、`RejectAllCommand` | 应用补丁 |

**`src/AgentWorkbench.App/ViewModels/ShellViewModel.cs`（骨架）**

```csharp
public sealed partial class ShellViewModel : ObservableObject
{
    private readonly IDocumentStore _store;
    private readonly DiffEngine _diff;
    private readonly IPatchService _patches;
    private readonly IAgentSessionFactory _agents;

    [ObservableProperty] private TableViewModel _table;
    [ObservableProperty] private ChatViewModel _chat;
    [ObservableProperty] private ReviewViewModel? _review;
    [ObservableProperty] private StatusViewModel _status;
    [ObservableProperty] private TableDocument? _document;

    [RelayCommand]
    private async Task ImportVersionAsync(CancellationToken ct)
    {
        var path = await _picker.PickCsvAsync();
        if (path is null) return;

        var incoming = await _store.ImportCsvAsync(path, ct);
        var result = _diff.Compare(Document!, incoming);
        if (result.IsFailure)
        {
            Status.Warn(result.Mismatch!.ToMessage());   // 列不一致，直接提示
            return;
        }

        Table.ApplyDiff(result.ChangeSet);              // 只染色，不改数据
        Status.Info($"对比完成：{result.ChangeSet.Headline}");
    }

    [RelayCommand]
    private void Undo()
    {
        var previous = _patches.Undo();
        if (previous is null) return;
        Document = previous;
        Table.Reload(previous);
        Status.Info($"已撤销，回到 v{previous.Version}");
    }
}
```

注意 `Table.ApplyDiff(...)` 只改颜色不改数据：**导入新版本是"看差异"，不是"覆盖"。** 覆盖要用户明确点"采用新版本"，这个动作放在 M2 的可选范围里，别默认做。

## 8.3 动态列怎么落到 DataGrid

表格列数由文档决定，XAML 里写不死。做法：文档加载后**用代码生成列**，每列一个 `DataGridTemplateColumn`，模板按列序号绑定到 `RowViewModel.Cells[index]`。

```csharp
private void BuildColumns(TableDocument doc)
{
    Grid.Columns.Clear();

    for (var i = 0; i < doc.Columns.Count; i++)
    {
        var index = i;                       // 闭包捕获，别直接用 i
        var column = doc.Columns[index];

        Grid.Columns.Add(new DataGridTemplateColumn
        {
            Header = column.Name,
            Width = new DataGridLength(1, DataGridLengthUnitType.Auto),
            CellTemplate = new FuncDataTemplate<RowViewModel>((row, _) =>
            {
                var text = new TextBlock
                {
                    Margin = new Thickness(8, 0),
                    VerticalAlignment = VerticalAlignment.Center
                };
                text.Bind(TextBlock.TextProperty, new Binding($"Cells[{index}].Display"));
                text.Bind(TextBlock.BackgroundProperty, new Binding($"Cells[{index}].Background"));
                text.Bind(TextBlock.FontWeightProperty, new Binding($"Cells[{index}].FontWeight"));
                return text;
            }, supportsRecycling: true)
        });
    }
}
```

三个坑，提前说：

- **`index` 必须先赋给局部变量再捕获。** 直接捕获循环变量，所有列都会绑到最后一列。
- **用整数索引，不要用中文列名做绑定路径。** `Cells[工号]` 这种路径在解析器里容易出问题；列顺序在加载后固定，索引是安全的。
- **`supportsRecycling: true` 必须开。** 否则 5000 行会创建 5000 个 `TextBlock`，滚动立刻掉帧。

`CellViewModel.Background` 返回 `IBrush`，颜色逻辑放在 ViewModel 里（而不是 XAML 触发器），因为 Avalonia 的样式触发器不如 WPF 灵活，代码里算更直接。

## 8.4 差异怎么画

三种状态三种视觉，且**不能只靠颜色**（色弱用户、投影仪偏色都会失效）：

| 状态 | 背景 | 附加标记 | 说明 |
| --- | --- | --- | --- |
| 修改 | 琥珀 `#33F59E0B` | 左侧 3px 竖条 + 加粗 | 原值放悬浮提示 |
| 新增行 | 绿 `#3322C55E` | 行首 `+` | 整行着色 |
| 删除行 | 红 `#33EF4444` | 行首 `−` + 删除线 | 保留在列表里，不真删 |
| 低置信度匹配 | 黄 `#33EAB308` | 行尾 `?` | 悬浮提示"按位置匹配，请核对" |
| 当前审阅项 | 蓝边 `#3B82F6` | 无 | 与审阅栏联动 |

四个实现要求：

1. **删除行要留在表里。** 直接从 `Rows` 移除，用户就看不到"删了什么"，也勾不了"不接受删除"。用一个 `IsDeleted` 标记，渲染成删除线。
2. **原值放 ToolTip，不要并排两列。** 并排会让列宽翻倍，5000 行时横向滚动很难用。
3. **颜色带 alpha（`#33` 前缀）。** 这样在深色和浅色主题下都能透出底色，不会糊成一块。
4. **审阅栏与表格双向联动。** 点审阅项，表格滚到对应行并高亮 2 秒；点表格里的改动格，审阅栏滚到对应项。这一步做出来，演示效果提升最明显。

## 8.5 对话区

消息不是纯文本，是五种卡片：

| 类型 | 长什么样 | 什么时候出现 |
| --- | --- | --- |
| `Text` | 普通气泡，支持 Markdown 子集（加粗、列表、行内代码） | 模型回答 |
| `ToolCall` | 默认折叠的一行：`▸ query_rows · 20 行 · 12ms` | 每次工具调用 |
| `Proposal` | 卡片：变更摘要 + "查看/接受/拒绝" | 收到提议 |
| `AskUser` | 问题 + 选项按钮 | 模型调 `ask_user` |
| `Error` | 红色左边框 + 一句人话 + "重试" | 网络/校验/超轮次 |

```csharp
public abstract class ChatItem : ObservableObject;
public sealed class TextItem(string text, bool isStreaming) : ChatItem;
public sealed class ToolCallItem(string name, string summary, TimeSpan elapsed) : ChatItem;
public sealed class ProposalItem(string proposalId, string headline) : ChatItem;
public sealed class AskUserItem(string question, IReadOnlyList<string> options) : ChatItem;
public sealed class ErrorItem(string message, string? retryHint) : ChatItem;
```

流式输出只更新最后一条 `TextItem`，不要每来一个字就重建整个列表——`ObservableCollection` 的 `Reset` 会让滚动条疯狂跳动。

**自动滚动规则**：只有当用户已经在底部时才跟随；用户向上翻阅历史时不要抢滚动。判断方法：`ScrollViewer.Offset.Y + Viewport.Height >= Extent.Height - 24`。

## 8.6 审阅栏

这是整个界面最重要的 200 像素。它必须回答三个问题：改几处、改哪里、我同意哪几处。

```csharp
public sealed partial class ReviewViewModel : ObservableObject
{
    public ObservableCollection<ReviewItemViewModel> Items { get; } = [];
    public string Headline => $"{ProposalId}：{Summary}";

    [ObservableProperty] private bool _allAccepted = true;

    [RelayCommand] private void AcceptSelected() => Submit(acceptedOnly: true);
    [RelayCommand] private void RejectAll() => Submit(acceptedOnly: false);
    [RelayCommand] private void ToggleAll() { /* 全选/全不选 */ }
}

public sealed partial class ReviewItemViewModel : ObservableObject
{
    [ObservableProperty] private bool _isAccepted = true;
    public string OpId { get; init; } = "";
    public string Display { get; init; } = "";   // "月薪 18000 → 18900（E1003）"
}
```

交互细节，都是演示时会被放大的地方：

- **默认全选。** 用户的心态是"先看，没问题就接受"，默认不选会让他多点 6 次。
- **`Enter` 接受、`Esc` 拒绝。** 演示时不用离开键盘。
- **接受后不要弹窗。** 在状态栏显示"已应用 6 处，可撤销"，配一个"撤销"按钮，比模态对话框舒服。
- **拒绝必须能填原因**（一个单行输入即可）。原因要回灌给模型，否则下一轮它原样再来。

## 8.7 三种非正常状态

正常路径只占演示的一半，剩下的一半是"看起来出问题了怎么办"。

| 状态 | 界面 | 文案 |
| --- | --- | --- |
| 没有文档 | 中间一块拖放区 + "打开示例数据"按钮 | "拖入 CSV，或打开示例数据" |
| 没有配置 Key | 顶部黄色横幅，不挡操作 | "未配置模型密钥，当前为 MOCK 演示模式。配置方法 →" |
| 模型调用中 | 输入框禁用，出现"停止"按钮，状态栏转圈 | "正在思考…（已 3.2s）" |
| 校验失败 | 对话里一条 `Error` 卡，列出错误码与人话 | "有 2 处无法应用：月薪不是数字；工号不可修改" |
| 网络失败 | 卡片 + "重试"按钮 | "连接模型失败，已重试 2 次" |
| 超轮次 | 卡片提示，保留已有提议 | "模型没能在 8 轮内完成，已有的 3 处变更仍可确认" |

最后一行体现一个设计取向：**失败时不要丢掉已完成的工作。** 提议已经算好、差异已经算好，就该让用户还能用。

## 8.8 线程与并发

一条铁律：**所有集合与属性变更都在 UI 线程。**

Agent 循环跑在后台（`Task.Run` 或直接在 async 上下文），每次要更新界面时：

```csharp
await Dispatcher.UIThread.InvokeAsync(() => Chat.Append(item));
```

四件事必须做对：

1. **单飞。** 一轮没结束时禁止再发，`SendCommand.CanExecute = !IsBusy`。
2. **可取消。** 一个 `CancellationTokenSource` 贯穿循环、HTTP 请求、工具执行；点"停止"立即取消，并把已收到的文本保留下来。
3. **防重复应用。** 审阅栏点两次"接受"，第二次要无效——用 `proposalId` 做幂等校验。
4. **长任务不阻塞启动。** 打开 5000 行 CSV 时先显示空表 + "加载中"，不要 `Thread.Sleep` 式假死。

## 8.9 快捷键

macOS 上 `Cmd`，Windows 上 `Ctrl`，用 `KeyGesture` 的平台修饰符：

| 快捷键 | 动作 |
| --- | --- |
| `Cmd/Ctrl + O` | 打开表格 |
| `Cmd/Ctrl + Shift + O` | 导入新版本对比 |
| `Cmd/Ctrl + S` | 保存 |
| `Cmd/Ctrl + Z` | 撤销上一次应用 |
| `Cmd/Ctrl + Enter` | 发送消息 |
| `Enter` | 接受当前审阅 |
| `Esc` | 拒绝 / 取消生成 |

别做太多。超过十个快捷键，用户一个也记不住。

## 本篇要点

- 三区一栏：表格左、对话右、审阅栏下方横跨全宽、状态栏常驻 `MOCK`。
- 五个 ViewModel 各管一段，Shell 只做协调，算法一律不进来。
- 动态列用代码生成 `DataGridTemplateColumn`，按整数索引绑定，必须开 `supportsRecycling`。
- diff 不能只靠颜色：背景 + 竖条 + 行首符号 + 删除线，四者叠加。
- 删除行留在表里（打删除线），否则用户没法"不接受删除"。
- 失败时保留已完成的工作，别让一轮网络抖动毁掉整次演示。

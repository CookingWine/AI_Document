## 9.1 Demo 的目标

**一句话：让人亲眼看到"AI 改了哪几格、我点头它才生效、点错了能退回来"。**

不是"做一个表格 AI 工具"，是"证明一条受控的变更管线能跑通"。这个区别决定了后面所有的取舍：凡是不能强化这条证明的功能，一律不做。

三条成功判据，缺一条就算没做成：

| 判据 | 检验方式 |
| --- | --- |
| 差异算得准 | 40 行样本，v1→v2 报出 6 改 2 增 1 删，中间插入不级联 |
| 变更拦得住 | 越权改只读列被拒，超量改动被拒，用户拒绝后数据不变 |
| 演示不翻车 | 断网、无 Key、模型报错三种情况下，演示仍能继续 |

## 9.2 功能边界

### 必须做（P0）

| 编号 | 功能 | 判据 |
| --- | --- | --- |
| F1 | 打开 CSV，识别主键，显示表格 | 40 行 7 列正确显示，主键列只读 |
| F2 | 保存为 `.table.json`，重新打开一致 | 往返后逐格相同 |
| F3 | 导入新版本 CSV，计算差异并高亮 | 报出正确计数，改动格变色 |
| F4 | 变更清单（行号、列名、原值、新值） | 与表格高亮一一对应 |
| F5 | 对话问答（只读） | "研发部几个人"答对，给出依据行 |
| F6 | 对话改数据（提议 → 预览） | 出审阅栏，表格预染，数据未变 |
| F7 | 逐条接受/拒绝，应用后生效 | 拒绝的那条不生效，其余生效 |
| F8 | 撤销 | 一次撤销回到应用前，逐格一致 |
| F9 | 审计日志 | 每次调用/提议/应用各一行 |
| F10 | Mock 模式 | 无 Key 时三段脚本可跑完 |

### 可以做（P1，时间有余才碰）

| 功能 | 成本 | 什么时候值得做 |
| --- | --- | --- |
| XLSX 导入 | 0.5 天 | 演示对象只用 Excel 时 |
| 导出 Markdown 报告 | 0.5 天 | 需要给领导留档时 |
| 多轮修正（拒绝后模型重提） | 0.5 天 | 想展示"AI 会改错也能改对" |
| 规则文件可视化编辑 | 1 天 | 观众里有"配置从哪来"的疑问 |
| 低置信度匹配提示 | 0.5 天 | 样本表没有主键时 |

### 明确不做

| 不做 | 原因 |
| --- | --- |
| 多表 / 多 Sheet / 表间关联 | 数据模型要重做，收益与 Demo 目标无关 |
| 公式、透视、图表 | 表格产品的功能，不是 Agent 管线的证明 |
| Excel 样式、合并单元格、图片 | 保真成本极高，Demo 只需要值 |
| 多人协作、云同步、账号 | 需要服务端，与"单机可演示"冲突 |
| 插件市场、多 Agent 编排 | 抽象需要第二个样本，现在没有 |
| 任意脚本 / SQL 执行 | 安全边界直接破防 |
| 超过 5000 行 / 50 列 | 性能优化是产品阶段的事 |
| 撤销历史持久化 | 内存够了，落盘要处理版本兼容 |

**边界不是能力上限，是承诺上限。** 写下来是为了在被追问"能不能再加个 XX"时，有一个可以指的东西。

## 9.3 六个里程碑

每个里程碑都按"目标 → 步骤 → 产出 → 验收 → 坑"写。步骤里的序号就是动手顺序，不要跳。

### M0 环境与骨架（0.5 天）

**目标**：一个能跑的空窗口 + 五个项目 + 正确的依赖方向。

**步骤**

1. 装 .NET 10 SDK，`dotnet --version` 确认 10.0.x（详见 [01](./01-从哪里开始.md) 1.2）。
2. 建解决方案与六个项目，用 `dotnet add reference` 接好依赖（[03](./03-工程骨架与约定.md) 3.1）。
3. 加 `Directory.Build.props`、`Directory.Packages.props`。
4. 写 `Program.cs`、`App.axaml.cs`，DI 注册 `ShellViewModel` 与 `MainWindow`。
5. 在 `App.axaml` 引入 Fluent 主题与 DataGrid 样式。
6. 主窗口放一个三行假数据的 `DataGrid`，确认渲染正常。
7. `git init` + 首次提交。

**产出**：可运行窗口、空的分层解决方案、`.gitignore`。

**验收**：`dotnet build` 零警告；`dotnet run` 出窗口；`dotnet list src/AgentWorkbench.Core reference` 为空。

**坑**

- 不引 DataGrid 主题样式，表格没有边框，看起来像坏了。
- 开了 `AvaloniaUseCompiledBindingsByDefault` 但 XAML 没写 `x:DataType`，编译直接报错。
- 在 macOS 上把 `net10.0-windows` 写进 `TargetFramework`，还原就失败。

---

### M1 数据层与表格显示（1 天）

**目标**：CSV 进得去、JSON 存得住、表格显示得对。

**步骤**

1. 写 `ColumnType`、`ColumnDef`、`CellValue`、`Row`、`TableDocument`（[04](./04-数据模型与存储.md) 4.2）。
2. 写 `TableDocument.Validate()`，实现 I1–I5 五条不变量。
3. 写 `CellValidator`：按列类型校验、值域校验、必填校验。
4. 写 `CsvTableReader`：表头解析、类型推断、空值区分、主键检测（三步，见 04.4）。
5. 写 `CsvTableWriter`：UTF-8 BOM、按列序输出、`null` 写空字段。
6. 写 `TableJsonStore`：序列化选项集中（中文不转义）、`schemaVersion`、原子写（先写 `.tmp` 再 `File.Move`）。
7. 造 `samples/employees.v1.csv`：7 列 40 行，含中文姓名、日期、金额、布尔。
8. 写 `TableViewModel` / `RowViewModel` / `CellViewModel` 与动态列生成（[08](./08-界面与交互.md) 8.3）。
9. 接上"打开文件"命令与拖放。
10. 单测：CSV → 文档 → JSON → 文档，逐格比对。

**产出**：能打开示例数据并显示的界面；`samples/employees.v1.csv`。

**验收**

- 打开 40 行 CSV，7 列全对，主键识别为"工号"，该列不可编辑。
- 另存 JSON，关掉重开，内容逐格一致。
- 5000 行 CSV 加载 < 800 ms（造一份压测数据试一次）。

**坑**

- CSV 里 `""` 和空字段被当成一样，往返后 `null` 变空串。
- 日期列被推断成文本，因为样本里有 `2021/3/15` 和 `2021-03-15` 两种写法——推断要支持多格式。
- 列 id 里带首尾空格，导致后面按列名查不到。
- JSON 默认编码器把中文写成 `\u5F20`，文件没法 review。

---

### M2 版本对比（1 天）

**目标**：导入 v2，准确说出哪里变了，并在表格上标出来。

**步骤**

1. 写 `CellComparer`：文本去空白、数字 `decimal`、日期多格式、布尔归一化、`null ≠ ""`（[05](./05-差异引擎.md) 5.3）。
2. 写 `DiffEngine.Compare`：列集合校验 → 主键配对 → 指纹配对 → 位置配对 → 增删收尾（5.6）。
3. 写 `ChangeSet` / `RowChange` / `CellChange` 与 `Headline`（5.4）。
4. 造 `samples/employees.v2.csv`：6 行修改、2 行新增、1 行删除，其中一处在中间插入。
5. `TableViewModel.ApplyDiff(changeSet)`：给 `CellViewModel` 打状态、算背景色。
6. 变更清单控件：`ListBox` 绑定 `ChangeSet.Rows`，显示行号 + 列名 + 原值→新值。
7. 选中清单项时表格滚动定位并临时高亮。
8. 写 `MarkdownReportWriter`（P1，但结构简单，顺手做掉）。
9. 把 5.9 的十条用例写成测试。

**产出**：对比功能、变更清单、diff 报告样例。

**验收**

- v1 → v2 报出"6 行修改（6 处）· 2 行新增 · 1 行删除"。
- 中间插入的那一行只算新增，后面所有行 0 变更。
- 把 v2 的列顺序调换再导入，报 0 变更。
- 十条用例全绿。

**坑**

- 行配对用行号，插入一行后全表变红——这是最典型也最致命的错。
- `Dictionary` 没传 `StringComparer.Ordinal`，遇到大小写或全半角差异时行为不可预期。
- 生成列时捕获了循环变量，所有列都绑到最后一列。
- 删除行直接从集合里移除，用户看不到"删了什么"。

---

### M3 只读 Agent（1.5 天）

**目标**：能用自然语言问表里的数据，答得对、有依据、不编造。

**步骤**

1. 写 `ChatClientFactory` 与 `AgentOptions`（[06](./06-Agent接入层.md) 6.2）。
2. 写 `MockChatClient` + `MockScripts`，先支持一句问答。
3. 写 `Prompts/system.md`（6.4 的四段结构）。
4. 写 `TableTools` 的四个只读工具，返回值统一 JSON 字符串（[07](./07-工具与权限门.md) 7.3）。
5. 写 `ToolDispatcher` 的只读分支 + 结构化错误回灌（6.7）。
6. 写 `AgentSession.SendAsync` 循环（6.6），暂不处理变更工具。
7. 写 `ChatViewModel`：消息集合、五种卡片、流式追加、取消（[08](./08-界面与交互.md) 8.5）。
8. 接审计日志：`chat.request`、`chat.response`、`tool.call`。
9. 状态栏显示模型名、`MOCK` 标记、tokens、耗时。
10. 写 3 条只读演示脚本并跑通（含一条"表里没有这个数据"）。

**产出**：可对话的只读助手。

**验收**

- 问"研发部有几个人"，答"6 人"并列出工号。
- 问"公司平均月薪"，答出数字，且与手算一致。
- 问"有没有叫赵六的"，表里没有，答"表里没有"，不编。
- 点"停止"能中断，已收文本保留。
- 断网时提示可读，不抛原始异常。

**坑**

- 回灌工具结果时丢了 `CallId`，下一轮 provider 直接 400。
- `query_rows` 没夹紧 `limit`，模型传 500，一次塞进上下文三万字。
- 把整张表塞进系统提示词——又贵又容易让模型开始"总结"而不是"查"。
- Mock 想做到"什么都能答"，结果变成一个需要调参的假模型。只覆盖脚本里的话就够了。

---

### M4 变更提议与确认门（1.5 天）

**目标**：模型能改数据，但改之前一定先给你看。

**步骤**

1. 写 `PatchOp`（`set_cell` / `add_row` / `delete_row`）、`TablePatch`、`PatchBuilder`。
2. 写 `PatchValidator` 的十二条规则（[07](./07-工具与权限门.md) 7.5），一次返回全部 issues。
3. 写 `PatchPreview`：Apply → Compare，产出预览 `ChangeSet`（禁止另写模拟逻辑）。
4. 扩展 `propose_changes` 工具，走"校验 → 暂存 → 返回 awaiting"分支（7.4）。
5. `AgentSession` 在收到 `AwaitingConfirmation` 时**结束本轮**，状态转 `AwaitingConfirm`。
6. 写 `ReviewViewModel` + 审阅栏（[08](./08-界面与交互.md) 8.6），默认全选。
7. 写 `PatchService.Apply`：先 `Push` 快照，再换文档，再写审计。
8. 实现 op 级接受：过滤 → 重建补丁 → **重新校验** → 应用。
9. 拒绝路径：丢弃补丁 → 回灌 `rejected_by_user` → 允许模型重提。
10. 撤销命令 + 状态栏"已应用 N 处，可撤销"。

**产出**：完整的变更闭环。

**验收**

- 说"研发部月薪低于 20000 的上调 8%"，出预览：行数、处数正确，表格预染，**数据未变**。
- 取消勾选其中一条再接受，被取消的那条不生效。
- 说"把工号改成 A 开头"，被 `READONLY_COLUMN` 拦下，对话里给出人话解释。
- 撤销一次，逐格回到应用前。
- 审计日志里 `patch.proposed` 的 `opCount` 大于 `patch.applied` 的 `opCount`。

**坑**

- 提议之后没结束循环，模型继续调工具，出现两个待确认提案，用户不知道该看哪个。
- 先换文档再 `Push` 快照，异常时丢掉撤销点。
- op 级接受后不重新校验，只接受"增 B"不接受"删 A"，直接撞主键。
- 拒绝后不回灌原因，模型下一轮原样再来一遍。
- 预览和实际应用用了两套逻辑，数字对不上——**只用 Apply + Compare 一条路径**。

---

### M5 打磨（1 天）

**目标**：从"能跑"到"敢在别人面前跑"。

**步骤**

1. 补齐三种非正常状态：无文档、无 Key、忙/错（[08](./08-界面与交互.md) 8.7）。
2. 快捷键：打开、导入、保存、撤销、发送、接受、拒绝（8.9）。
3. 低置信度提示（`≈` / `?`）与横幅（[05](./05-差异引擎.md) 5.7）。
4. 报告导出接上按钮。
5. 深色/浅色主题各看一遍，调对比度。
6. 5000 行压测：滚动、diff、应用各测一次。
7. 跑 [10](./10-测试与验收.md) 的十二条验收用例，记录结果。
8. 录一段 3 分钟屏，自己看一遍，把所有"卡一下""闪一下"的地方修掉。

**产出**：可演示版本 + 验收记录。

**验收**：十二条验收用例全部通过；压测无卡顿；深浅主题均可读。

**坑**

- 深色主题下 diff 背景色对比度不够，看不出改了哪格。
- 流式输出每来一个字就重建列表，滚动条乱跳。
- 审阅栏出现时挤压表格，列宽跳变。

### M6 打包交付（1 天）

**目标**：换一台机器，解压就能跑。

**步骤**

1. 按 [11](./11-打包与交付.md) 发布 macOS（arm64）与 Windows（x64）两个包。
2. 写 `README.md`（运行方式、配置方式、已知限制）。
3. 写 `docs/demo-script.md`（三段台词 + 预期）。
4. 整理 `docs/acceptance.md`（十二条用例 + 截图）。
5. 把 `artifacts/` 里的样例报告、审计日志放进去。
6. 在一台**没装过 .NET** 的机器上试跑一次。

**产出**：交付包 + 三份文档。

**验收**：解压 → 双击 → 打开示例 → 三段脚本跑完，全程不需要命令行。

**坑**

- 只发了 framework-dependent 包，对方没装运行时，双击没反应。
- macOS 未签名，Gatekeeper 直接拦，需要右键打开或 `xattr -d com.apple.quarantine`。
- 把 `samples/` 漏在包外，示例数据打不开。

## 9.4 排期与依赖

```
M0 ──▶ M1 ──▶ M2 ──┬──▶ M3 ──▶ M4 ──▶ M5 ──▶ M6
                   │
                   └─（M2 是关键路径，压缩它会让 M4 的预览不可信）
```

| 里程碑 | 天数 | 依赖 | 可否并行 |
| --- | --- | --- | --- |
| M0 | 0.5 | — | 否 |
| M1 | 1 | M0 | UI 与数据层可两人并行 |
| M2 | 1 | M1 | 否，核心路径 |
| M3 | 1.5 | M1（不依赖 M2） | 可与 M2 并行，但要先定好 `TableTools` 接口 |
| M4 | 1.5 | M2 + M3 | 否 |
| M5 | 1 | M4 | 否 |
| M6 | 1 | M5 | 否 |

如果只有一个人：7.5 天，按顺序做。如果有两个人：一人 M1→M2，一人 M3 的客户端与 Mock，在 M4 汇合。

**排期上最危险的动作是把 M2 的时间挪给 M4。** M2 少一天，M4 的预览就会和实际结果对不上，而这恰恰是 Demo 唯一的卖点。

## 9.5 演示脚本

三段，总时长 6–8 分钟。每段都写清"说什么、点什么、应该看到什么"，验收时照着念。

### 第一段：对比（2 分钟）

> "这是上个月的员工表，40 人。这是这个月的。"
> （点"导入新版本"，选 v2）

**应该看到**：状态栏"对比完成：6 行修改（6 处）· 2 行新增 · 1 行删除"。表格里 6 个格子变琥珀色，2 行变绿，1 行变红带删除线。

> "点这一行——李娜，月薪从 18000 变成 18900。中间这行是新来的周敏，不影响后面任何一行。"

**这一段证明**：差异算得准，且有稳定行标识。

### 第二段：问答（1.5 分钟）

> "研发部现在几个人？平均月薪多少？"

**应该看到**：模型先调 `query_rows`（折叠的一行），然后回答"6 人，平均 20,833 元"，并列出工号。

> "它没有把整张表读一遍，只查了研发部这 6 行。每次查了什么，这里都记着。"

**这一段证明**：模型是按需查询，不是靠上下文硬背；回答有依据。

### 第三段：改数据（3 分钟）

> "把研发部月薪低于 20000 的上调 8%。"

**应该看到**：模型查两次、提议一次。下方审阅栏出现"修改 3 行 共 3 处"，表格对应格子预染但**数值没变**。

> "注意，现在还没改。它只是提了个方案。"

（取消勾选其中一条）

> "这条我不太同意，去掉。"

（点"接受"）

**应该看到**：表格数值变成新值，状态栏"已应用 2 处，可撤销"。

> "改完了。要是反悔——"

（`Cmd+Z`）

**应该看到**：数值回到原样，状态栏"已撤销，回到 v3"。

**这一段证明**：确认门、逐条接受、可撤销，三件事同时成立。

### 加分第四段：越权（1 分钟，可选）

> "把所有人的工号前面加个 A。"

**应该看到**：对话里一条错误卡"工号列不可修改（只读列）"，数据无变化。

> "它试了，但改不动。这类规则不写在提示词里，写在代码里。"

### 质量标准

| 维度 | 标准 | 检验方法 |
| --- | --- | --- |
| 可复现 | 同输入同输出（温度 0、RowId 确定性） | 同一脚本跑三遍，diff 报告逐字节相同 |
| 可离线 | 无 Key 时功能不缺失，只是模型变 Mock | 拔网线跑三段脚本 |
| 错误可读 | 所有面向用户的错误都是中文人话 | 逐个触发 6.8 的七种失败 |
| 可追溯 | 每次改动都有审计行 | 应用后 `grep proposalId` 能查到完整链路 |
| 可回退 | 任何应用都能撤销 | 随机点 10 次应用再撤销，逐格核对 |
| 体积 | 安装包 < 150 MB | `du -sh` |

### 不接受的"完成"

- 只有 happy path，一断网就白屏。
- 预览靠"再算一遍差不多的逻辑"，和实际结果有偏差。
- 撤销只能退一步，或者退完数据不对。
- 审计日志只记"用户点了按钮"，不记改了什么。
- 演示时必须开两个终端、改一行代码、手动拷贝文件。

## 9.7 时间不够时，按这个顺序砍

1. **砍 P1 全部**（XLSX、报告导出、多轮修正、规则编辑）——不影响主线。
2. **砍演示第四段**（越权拦截）——少一个亮点，但主线完整。
3. **撤销栈退化为单步**——够演示，够说明问题。
4. **审计日志只记 `patch.applied`**——保留最关键的一条。
5. **对话改成非流式**——体验差一点，功能不受影响。

**不能砍的三样**：差异计算的准确性、确认门、撤销。砍掉任何一个，这个 Demo 就没有存在理由了。

## 本篇要点

- Demo 的目标是"证明一条受控变更管线"，不是"做一个表格工具"。所有取舍服从这一条。
- 六个里程碑 7.5 天，M2 是关键路径，不能挪时间给 M4。
- 每个里程碑都有明确的验收动作，做完就打勾，别攒到最后一起验。
- 演示脚本按"对比 → 问答 → 改数据 → 越权"讲，每段都对应一个技术证明。
- 输出要求里最容易被忽略的是"无 Key 可跑"和"解压即跑"，而它们恰恰决定演示当天会不会翻车。

## 4.1 四个类型，一条不变量

表格听起来简单，落到类型上只需要四个东西：

| 类型 | 是什么 | 一句话 |
| --- | --- | --- |
| `TableDocument` | 整张表 | 一次快照，不可变，改一个格子就产生新快照 |
| `ColumnDef` | 列的定义 | 名字、类型、必填、只读、值域 |
| `Row` | 一行 | 一个稳定 Id + 一组单元格 |
| `CellValue` | 一个格子 | **只存原始字符串**，类型判断交给列定义 |

第四行是这份设计里最值得解释的决定：**单元格不存 `object`，存字符串。**

因为表格数据的真实形态就是文本。`1.10` 和 `1.1` 在语义上相等，在字符串上不等；`2026-01-01` 和 `2026/1/1` 是同一个日期，写法不同。如果导入时就把它们塞进 `decimal` 和 `DateTime`，你会立刻遇到三个麻烦：精度丢失、格式还原不回去、以及"用户看到的"和"存下来的"不一致。

正确做法是：**原文照存，比较时按列类型归一化。** 这一条同时解决了显示、往返保存、类型校验三个问题。归一化规则在 [05 差异引擎](./05-差异引擎.md) 5.3 集中定义，只写一处。

## 4.2 代码

**`src/AgentWorkbench.Core/Model/ColumnDef.cs`**

```csharp
namespace AgentWorkbench.Core.Model;

public enum ColumnType { Text, Number, Date, Bool }

public sealed record ColumnDef(
    string Id,                              // 列标识，Demo 里等于表头文本
    string Name,                            // 显示名
    ColumnType Type,
    bool Required = false,
    bool ReadOnly = false,
    string? Format = null,                  // 显示格式，如 "0.00"、"yyyy-MM-dd"
    IReadOnlyList<string>? AllowedValues = null)  // 值域，null 表示不限
{
    public bool HasValueDomain => AllowedValues is { Count: > 0 };
}
```

**`src/AgentWorkbench.Core/Model/CellValue.cs`**

```csharp
namespace AgentWorkbench.Core.Model;

/// <summary>单元格只保存原始文本；null 表示空值，空字符串表示"确实填了空"。</summary>
public readonly record struct CellValue(string? Raw)
{
    public static CellValue Null => default;
    public static CellValue Of(string? raw) => new(raw);

    public bool IsNull => Raw is null;
    public bool IsBlank => string.IsNullOrWhiteSpace(Raw);

    public override string ToString() => Raw ?? string.Empty;
}
```

**`src/AgentWorkbench.Core/Model/Row.cs`**

```csharp
namespace AgentWorkbench.Core.Model;

public sealed record Row(string Id, IReadOnlyDictionary<string, CellValue> Cells)
{
    /// <summary>不变量：每一行都包含全部列，缺的列以空值补齐。</summary>
    public CellValue this[string columnId] =>
        Cells.TryGetValue(columnId, out var value) ? value : CellValue.Null;
}
```

**`src/AgentWorkbench.Core/Model/TableDocument.cs`**

```csharp
namespace AgentWorkbench.Core.Model;

public sealed record TableDocument(
    string Id,
    string Name,
    int Version,
    IReadOnlyList<ColumnDef> Columns,
    IReadOnlyList<Row> Rows,
    string PrimaryKeyColumnId,          // 必须存在，规则见 4.4
    DateTimeOffset UpdatedAt)
{
    public ColumnDef PrimaryKey =>
        Columns.First(c => c.Id == PrimaryKeyColumnId);

    public ColumnDef? FindColumn(string idOrName) =>
        Columns.FirstOrDefault(c => c.Id == idOrName)
        ?? Columns.FirstOrDefault(c => string.Equals(c.Name, idOrName, StringComparison.Ordinal));

    public Row? FindRow(string rowId) =>
        Rows.FirstOrDefault(r => string.Equals(r.Id, rowId, StringComparison.Ordinal));

    public TableDocument Bump(DateTimeOffset now) =>
        this with { Version = Version + 1, UpdatedAt = now };
}
```

`FindColumn` 同时接受 Id 和显示名，是给模型用的：模型看到的是"月薪"，而代码里 Id 可能也是"月薪"，但表格一旦改成 `salary` 也能命中。这个宽容度值得保留。

## 4.3 五条不变量

不变量就是"任何时候都必须成立"的断言。破了，后面所有逻辑都不作数。建议在 `TableDocument` 上加一个 `Validate()`，每次导入、每次应用补丁后都跑一遍（Debug 下用 `Debug.Assert`，Release 下记日志）。

| 编号 | 不变量 | 破了会怎样 | 谁负责守 |
| --- | --- | --- | --- |
| I1 | `PrimaryKeyColumnId` 指向的列必须存在 | 差异无法配对 | 导入时校验 |
| I2 | 每行 Id 等于主键列的原始值，且全表唯一 | 改错行、diff 错乱 | 导入 + 补丁校验 |
| I3 | 每行包含全部列 | 显示时出现空白列、比较时误判 | 导入 + 补丁应用 |
| I4 | 每列的值符合该列类型（或为空） | 排序、聚合、比较全部失真 | 补丁校验 + 导入校验 |
| I5 | 列顺序稳定，不在运行期增删列 | diff 把列变化误报成数据变化 | Demo 不做列编辑 |

I2 值得多解释一句：**行 Id 不另生成，直接用主键值。** 这样模型说"改 E1007 的月薪"，你不需要再做一次映射，日志里也一眼能看懂。代价是主键列必须只读——改主键等于换了一个人，那是删除加新增，不是修改。

## 4.4 主键从哪来

导入 CSV 时按顺序判断，命中就停：

1. **表头名匹配**：`工号`、`编号`、`ID`、`id`、`No`、`code` 之一 → 用它。
2. **内容像唯一键**：某列全部非空、无重复、长度 ≤ 32、不含换行 → 提示用户确认为主键。
3. **都没有**：注入隐藏列 `__rowid`，值 `r-000001` 递增，`ReadOnly=true`，界面上隐藏。

第三步是兜底，也是很多表格工具偷懒跳过的一步。跳过之后，一旦用户在中间插入一行，diff 会把后面所有行判成"修改"，演示当场翻车。

**主键列一律 `ReadOnly = true`。** 这是硬约束，写在导入逻辑里，不靠用户记得。

## 4.5 JSON 格式

真源格式，扩展名 `.table.json`，缩进 2 空格（要进 Git，要能人眼读）。

```json
{
  "schemaVersion": 1,
  "id": "doc-20261105-001",
  "name": "员工花名册",
  "version": 3,
  "primaryKeyColumnId": "工号",
  "updatedAt": "2026-11-05T10:12:00+08:00",
  "columns": [
    { "id": "工号", "name": "工号", "type": "text", "required": true, "readOnly": true },
    { "id": "姓名", "name": "姓名", "type": "text", "required": true },
    { "id": "部门", "name": "部门", "type": "text", "required": true },
    { "id": "职级", "name": "职级", "type": "text" },
    { "id": "入职日期", "name": "入职日期", "type": "date", "format": "yyyy-MM-dd" },
    { "id": "月薪", "name": "月薪", "type": "number", "format": "0.00" },
    { "id": "在职", "name": "在职", "type": "bool" }
  ],
  "rows": [
    {
      "id": "E1001",
      "cells": {
        "工号": "E1001",
        "姓名": "张伟",
        "部门": "研发",
        "职级": "P6",
        "入职日期": "2021-03-15",
        "月薪": "24000",
        "在职": "true"
      }
    }
  ]
}
```

四个设计点：

- **`cells` 是对象不是数组。** 好处是可读、可缺省；代价是文件大一点。5 万格以内无所谓。
- **`schemaVersion` 单独存在。** 以后格式变了，靠它做迁移，不靠猜。
- **`version` 是文档版本号，每次应用补丁 +1。** 审计日志靠它对齐。
- **列 id 用中文。** 这个决定牺牲了一点"工程洁癖"，换来的是 CSV 往返零映射、模型直接用中文列名、日志可读。Demo 阶段值得。

序列化用一个静态类集中管理，别在十个地方 `new JsonSerializerOptions()`：

```csharp
public static class TableJson
{
    public static readonly JsonSerializerOptions Options = new()
    {
        WriteIndented = true,
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,  // 中文不转 \uXXXX
        Converters = { new JsonStringEnumConverter(JsonNamingPolicy.CamelCase) }
    };
}
```

`UnsafeRelaxedJsonEscaping` 是必须的：默认编码器会把"张伟"写成 `\u5F20\u4F1F`，文件没法看，diff 也没法 review。

## 4.6 CSV 导入导出

CSV 看着简单，坑全在细节里。规则先定死，别边写边想：

| 情况 | 处理 |
| --- | --- |
| 编码 | 读：UTF-8（有 BOM 无 BOM 都吃）；写：UTF-8 **带 BOM**（否则 Excel 打开是乱码） |
| 分隔符 | 逗号。检测到分号/制表符时提示，不自动猜 |
| 引号 | `"` 包裹，内部 `""` 转义，支持字段内换行 |
| 空字段 | 不带引号的空 → `null`；带引号的 `""` → 空字符串 |
| 表头 | 第一行，去首尾空白，空表头报错，重名报错 |
| 类型推断 | 全列能解析为数字 → `Number`；能解析为 `yyyy-MM-dd` 或 `yyyy/M/d` → `Date`；只有 `true/false` → `Bool`；否则 `Text`。有任一空值不影响推断 |
| 行数上限 | 5000 行，超出提示并拒绝（Demo 边界） |
| 列数上限 | 50 列 |

类型推断只做一次，结果写进 JSON 后**不再重算**。否则用户手动把某列改成文本，下次导入又被推回数字。

解析用 `CsvHelper`（MIT/Apache 双许可），别自己写。自己写会在"字段内换行 + 转义引号 + BOM"三件套上翻车，而这三件事在真实表格里全都出现过。

**`src/AgentWorkbench.Infrastructure/Storage/CsvTableReader.cs`（骨架）**

```csharp
public sealed class CsvTableReader
{
    public async Task<TableDocument> ReadAsync(string path, CancellationToken ct)
    {
        using var reader = new StreamReader(path, Encoding.UTF8, detectEncodingFromByteOrderMarks: true);
        using var csv = new CsvReader(reader, new CsvConfiguration(CultureInfo.InvariantCulture)
        {
            BadDataFound = null,
            MissingFieldFound = null,
            DetectDelimiter = false
        });

        await csv.ReadAsync();
        csv.ReadHeader();
        var headers = (csv.HeaderRecord ?? []).Select(h => h.Trim()).ToArray();
        // ……建列、推断类型、逐行读取、确定主键（见 4.4）
    }
}
```

导出反过来：按列顺序写表头，值取 `CellValue.Raw`，`null` 写成空字段。**不要**在导出时做格式化（比如把 `24000` 写成 `24,000.00`），格式化是显示层的事，写回文件只写原值。

## 4.7 版本、快照与撤销

三个概念别混：

| 概念 | 含义 | 存在哪 |
| --- | --- | --- |
| `Version` | 文档改过几次，每次应用补丁 +1 | JSON 里，持久化 |
| 快照（Snapshot） | 某个版本的完整 `TableDocument` 对象 | 内存，撤销栈 |
| 审计记录 | 谁在什么时候改了什么 | JSONL 文件，追加写 |

撤销栈就三行代码，因为文档不可变，快照几乎不要钱（只是引用）：

```csharp
public sealed class DocumentHistory(int capacity = 30)
{
    private readonly Stack<TableDocument> _undo = new();

    public bool CanUndo => _undo.Count > 0;

    public void Push(TableDocument before)
    {
        _undo.Push(before);
        if (_undo.Count > capacity) TrimBottom();
    }

    public TableDocument? Undo(TableDocument current) =>
        _undo.TryPop(out var previous) ? previous : null;

    private void TrimBottom() { /* 用 Queue 辅助或换 List 实现，见实现注记 */ }
}
```

`Stack<T>` 不能从底部删，超过容量时换 `List<TableDocument>` 按索引管理更省事。这是实现细节，别在这里纠结，先让 `CanUndo/Undo` 语义正确。

**注意**：撤销栈只在内存里。关掉程序，撤销历史就没了——这是 Demo 的明确边界，不要为了"关掉还能撤"去做持久化历史，那是产品阶段的事。

## 4.8 性能边界

Demo 承诺的范围：**≤ 5000 行 × 50 列**。超了不保证，界面上给提示。

| 操作 | 目标 | 说明 |
| --- | --- | --- |
| 加载 5000×50 JSON | < 300 ms | `System.Text.Json` 直接反序列化，别用 Newtonsoft |
| 加载同规模 CSV | < 800 ms | CsvHelper 逐行读，边读边建对象 |
| 全表 diff | < 150 ms | 字典索引配对，不用嵌套循环 |
| 应用 200 条补丁 | < 100 ms | 一次性重建集合，别逐条 `with` |
| 表格滚动 | 60 fps | DataGrid 虚拟化默认开启，别关 |

超过这个量级要换方案（分页加载、增量 diff、列式存储），但那是产品阶段，Demo 不碰。第 12 篇 12.4 列了该换架构的信号。

## 本篇要点

- 四个类型：文档、列定义、行、单元格。**单元格只存原始字符串**，类型判断交给列定义。
- 五条不变量里，最关键是"行 Id 等于主键值且唯一"——它让 diff、补丁、日志三处都能对上号。
- 主键按"表头名 → 内容唯一性 → 注入 `__rowid`"三步取，**主键列一律只读**。
- JSON 用缩进 + 中文不转义，是为了能进 Git、能 review；`schemaVersion` 为以后留门。
- CSV 的类型推断只做一次，结果写进 JSON 后不再重算。

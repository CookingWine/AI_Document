# 01 什么是规则

## 1.1 先从你每天在守的东西说起

你今天已经守了很多规则，只是没觉得那是规则。

- 开车过路口，**红灯停**。没人每次都提醒你，你也不会先问一句"今天要停吗"。
- 进公司大门要**刷卡**。卡不对，门就是不开。
- 小区门口写着"**外来车辆禁止入内**"。它不需要保安每次请示领导，就贴在那儿。

这三件事有个共同点：**它们是提前定好、一直在生效的，不需要每次重新商量。**

这就是规则最朴素的样子。它不教你怎么开车，也不告诉你今天去哪儿——它只划定**能做什么、不能做什么**的边。

---

## 1.2 规则有三个脾气

理解这三个脾气，后面所有内容都能顺下来。

**第一个脾气：它一直在，不用谁来喊。**

红绿灯不需要你申请才生效。规则的价值恰恰在于"**你忘了它也在**"。一份存在硬盘角落、要用的时候才想起来的文件，不是规则，是资料。

**第二个脾气：它管边界，不管步骤。**

"不许闯红灯"是规则；"先踩离合再挂挡，松手刹，缓抬离合"是操作步骤。规则回答**能不能**，步骤回答**怎么做**。

这个区别很要紧。规则写多了步骤，就会又长又难守；步骤写成了规则，就会天天误伤。

**第三个脾气：它是给"所有人"的，不是给"这一次"的。**

"今天下雨，路上慢点"——这句话只对今天有效，是提醒，不是规则。
"雨天限速 60"——写在路边牌子上，年年有效，这才是规则。

> 💡 **一句话判断**
> 你这条要求，**下个月还用得上吗？** 用得上，可能是规则；只对这次有用，那就是一句交代，别硬写成规则。

## 1.3 换成 AI，为什么更需要规则

把上面那套搬到 AI 身上，会发现问题被放大了。

AI 有点像一位**能力很强、但今天第一次来你公司上班的同事**：书读得多、手也快，可他不了解你的习惯、不知道你上次被坑过什么、也不清楚哪些文件是碰不得的。

于是最容易出的岔子，不是"他不会"，而是这三类：

| 岔子 | 现场长什么样 |
| --- | --- |
| **做过了头** | 你让它改一段文字，它顺手把整个文档的格式也重排了 |
| **自作主张** | 你没给数字，它"合理地"编了一个，还写得很像真的 |
| **忘了上次** | 昨天刚说过"别用感叹号"，今天新开一个对话，它又开始感叹 |

这三类事的共同点是：**它会重复发生，而你每次都得重新说一遍。**

规则就是用来终结这个循环的。写一次，放在它每次开工都能看见的地方，往后就不用再提。

> ⚠️ **别误会一件事**
> 规则不是"让它变聪明"。它该不会的还是不会。
> 规则解决的是另一件事：**让它别做那些你没允许的事**。这两件事完全不同，别指望用规则补能力。

---

## 1.4 一条规则由四个零件组成

这是本篇最有用的一节。以后你判断"这条规则写得行不行"，就看这四个零件齐不齐。

| 零件 | 回答什么问题 | 缺了会怎样 |
| --- | --- | --- |
| **对象** | 这条规则管谁、管哪类事 | 什么活都往上套，误伤 |
| **要求** | 具体要做什么 / 不许做什么 | 说了等于没说 |
| **判据** | 怎么算做到了、怎么算违规 | 各说各话，没法验收 |
| **例外** | 什么情况下可以不这样 | 遇到特殊情况只能硬碰，或者被悄悄破坏 |

看一个真实的对比。

**❌ 缺零件的一条**

```
回答要专业一点。
```

这句话四个零件里只勉强有个"要求"，而且"专业"这个词，你和 AI 的理解大概率不一样。它可能理解成"多用术语"，而你想要的是"别啰嗦"。

**✅ 四个零件都齐的一条**

```
【对象】所有对外发出的回复
【要求】不用"亲""哈""~"这类语气词，不用感叹号
【判据】发出去之前自查一遍：出现上述任一符号就改掉
【例外】客户主动用轻松语气且已成交的老客户，可少量使用"哈"
```

同一条规矩，第二种写法 AI 照着做就不会跑偏，你事后检查也有依据。

> 💡 **不必每次都写全四个**
> 简单规则写到"对象 + 要求"就够用。但**只要你发现自己需要反复纠正同一件事**，就说明缺的是"判据"或"例外"，补上就好。

## 1.5 规则和"交代一件事"不是一回事

这两件事天天被混在一起，混了就会写出又长又没用的规则。

| 对比项 | 交代一件事（派活） | 立一条规则 |
| --- | --- | --- |
| 说一次管多久 | 只管这一次 | 一直管 |
| 内容长什么样 | "把这周的销售数据整理成表" | "任何数字都必须有出处，没有就标【待确认】" |
| 谁来定 | 你定，AI 执行 | 你定，AI 每次自动遵守 |
| 写错了的后果 | 这次重做 | 往后每一次都错 |
| 该放哪儿 | 对话里说 | 写在规则文件里 |

最后两行是关键。**派活写错，成本是一次；规则写错，成本是每一次。** 所以规则值得多花十分钟推敲，派活不必。

反过来说：**别把一次性的活写成规则。** 你的规则文件里每多一条只用过一次的规矩，AI 每次开工就多读一句废话，真正重要的那几条反而被稀释了。

---

## 1.6 你其实早就在写规则了，只是没写下来

回想一下，你有没有对 AI 说过这些话：

- "别给我加总结。"
- "不要用 markdown 表格。"
- "中文回答。"
- "改的时候只改我指出的地方，别动别的。"

这些**全都是规则**，而且都是好规则——短、明确、能判断。

问题是：它们现在散落在几十个对话框里，每开一个新对话就归零一次。

AIRule 做的事，说白了只有一件：**把这类话从"每次口头说"，变成"写在一张纸上，贴在它门口"。**

## 本篇小结

| 要点 | 一句话记住 |
| --- | --- |
| 规则的第一个脾气 | 一直在，不用谁来喊 |
| 第二个脾气 | 管边界，不管步骤 |
| 第三个脾气 | 给"以后所有次"，不给"这一次" |
| 四个零件 | 对象、要求、判据、例外 |
| 和派活的区别 | 派活错一次，规则错每次 |
| AIRule 干的事 | 把口头说的话，写成一张贴在门口纸 |

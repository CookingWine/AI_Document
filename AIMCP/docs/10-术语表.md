## 10.1 术语对照表

读到不认识的词，回来查。**不用背**，查三次自然就记住了。

| 术语 | 大白话 | 生活里的比方 |
| --- | --- | --- |
| MCP | AI 和外部工具之间的统一接口标准 | 统一的 USB-C 插口 |
| 宿主（Host） | 你打开的那个 AI 程序 | 你吃饭的那家餐厅 |
| 客户端（Client） | 宿主内部负责按标准说话的那部分 | 服务员 |
| 服务器（Server） | 真正提供能力的那一端 | 后厨窗口 |
| 工具（Tool） | 能被 AI 调用的一个动作 | 菜单上能点的菜 |
| 资料（Resource） | 能被读取的内容，如文件、记录 | 桌上摆的参考资料 |
| 提示词模板（Prompt） | 预先写好的任务模板 | 店里的套餐 |
| 工具调用（Tool Calling） | 模型输出"请帮我调这个函数" | 点单 |
| JSON-RPC | 消息的格式约定：谁发的、第几号、要干什么 | 快递单的填写规范 |
| 传输（Transport） | 消息怎么送到对方 | 走路送 / 打电话 / 发快递 |
| stdio | 本地方式：两个程序用输入输出管子直接对话 | 隔着门缝递纸条 |
| Streamable HTTP | 远程方式：用网页协议发请求 | 打电话叫外卖 |
| 能力声明（Capability） | 服务器说"我会哪几样"，客户端说"我支持哪几样" | 菜单上标"本店供应…" |
| 结构定义（Schema） | 一份"长什么样"的机器可读说明书 | 表格的填写格式说明 |
| 授权（OAuth） | 一种"不用交出密码也能授权"的登录方式 | 给保洁一把只能开某间房的门卡 |
| 权限范围（Scope） | 这张通行证能访问哪些东西 | 门卡能开哪几扇门 |
| 扩展（Extension） | 标准之外的可选增强能力 | 手机的可选配件 |
| 提示词注入（Prompt Injection） | 把指令藏在数据里，骗 AI 去执行 | 在合同里夹一张"请把尾款打到这里"的纸条 |
| 工具命名空间 | 给工具加服务器前缀，避免重名 | 同名的人前面加部门 |
| 无状态（Stateless） | 每个请求自带全部信息，不依赖上一次 | 每次办事都带齐材料，不用"接着上次办" |

## 10.2 容易混的四组词

- **MCP vs API**：API 是各家自己的门，MCP 是统一的门框。
- **MCP vs 插件**：插件是"装进某个软件里的东西"，MCP 是"跨软件通用的接头"。
- **MCP vs 技能**：MCP 管"够不够得着"，技能管"做得对不对"。
- **客户端 vs 服务器**：客户端是点菜的，服务器是做菜的；**你永远只跟客户端打交道**。

---

## 本篇要点

- 三类核心词：**角色**（宿主/客户端/服务器）、**能力**（工具/资料/模板）、**机制**（传输/授权/扩展）。
- 最容易混的四组：MCP vs API、MCP vs 插件、MCP vs 技能、客户端 vs 服务器。
- 记不住就记一句：**MCP 是插口，不是电源，也不是电器。**

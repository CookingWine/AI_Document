## 9.1 如果你在网上看到旧教程

MCP 这几年改得很快。看到对不上的地方，先看文章的日期。

| 时间 | 发生了什么 | 对写配置的人有影响吗 |
| --- | --- | --- |
| 2024-11 | Anthropic 首次发布 MCP | — |
| 2025 年 | 陆续加入授权、流式传输、工具注解等；各客户端开始支持 | 配置格式基本稳定 |
| 2025-12 | 交由 Linux 基金会下的 Agentic AI Foundation 托管 | 不影响使用 |
| **2026-07-28** | 发布至今最大的一次修订：**无状态核心**，取消初始化握手与会话；新增 `server/discover`；服务器反向请求改为"多轮往返"；引入扩展框架（界面、长任务、企业授权）；授权加固；正式废弃 `roots`、`sampling`、`logging` | 对"填配置"的人几乎无感；对"写服务器"的人影响很大 |

**你需要记住的三件事**：

1. **配置格式没变**：还是 `mcpServers` 里写 `command`/`args`/`env` 或 `url`/`headers`。
2. **新服务器建议按 2026-07-28 版写**；老服务器仍能用，协议保留了对旧版本的兼容。
3. **看到"先 initialize 握手""Mcp-Session-Id""SSE 长连接"这类说法**，那是 2025 年的写法。不是错，是旧。

> 协议版本号就是日期，形如 `2026-07-28`。这个设计挺聪明：看到版本号就知道是哪一天的规矩。

## 9.2 十个常见误区

| # | 误区 | 实际上 |
| --- | --- | --- |
| 1 | MCP 是某个 AI 产品的功能 | 它是公开标准，多家客户端和模型都支持 |
| 2 | 装了 MCP，AI 就变强了 | 它只是多了几件工具；会不会用、用得对不对，仍取决于提示词和技能 |
| 3 | MCP 能保证安全 | 安全靠权限配置、只读优先、确认门；协议只管说话方式 |
| 4 | MCP 是一个插件市场 | 它不提供下载；服务器从哪来是另一件事 |
| 5 | 工具越多越好 | 工具太多，模型会选错、会乱调；按需启用 |
| 6 | 密钥写在配置里方便 | 一次截图、一次提交，就可能被盗刷 |
| 7 | 给它整个硬盘的权限，省得麻烦 | 这正是最危险的做法；只给一个子文件夹 |
| 8 | MCP 能记住我的偏好 | 记忆在规则文件、技能文件、对话上下文里，不在协议里 |
| 9 | MCP 服务器一定要联网 | 本地的 stdio 服务器完全不用网络 |
| 10 | 配一次永远有效 | 服务器会升级、路径会变、协议会迭代；出问题先重启、再重看配置 |

## 9.3 十个常见问题

**Q1：我需要会编程吗？**
用现成的服务器：不需要。你只需要会改配置文件里的几个值。
自己写一个服务器：需要一点编程基础（Python、TypeScript、Go、C# 都有官方工具包）。

**Q2：MCP 和普通的 API 有什么区别？**
API 是"每个系统自己开的一扇门"，门的大小、敲门方式、递东西的格式各家不同。
MCP 是"统一的门框和说话方式"：门后面还是那套 API，但外面的人不用再学一遍。

**Q3：MCP 和"工具调用"是什么关系？**
工具调用是**模型的能力**（它会说"我要调这个函数"）；MCP 是**工具的接入标准**（规定这个函数怎么描述、怎么被找到、结果怎么回来）。
没有 MCP，工具调用照样能用，只是每接一个工具都要自己写一遍。

**Q4：MCP 和技能（AISkill）是什么关系？**
接口 vs 做法。MCP 让 AI 够得着工具；技能告诉它"这类活按什么步骤做、什么不许做"。两者互补。

**Q5：本地和远程怎么选？**
数据敏感、只处理本机文件 → 本地。多人共用、要连公司系统 → 远程。
拿不准时，先用本地只读的试。

**Q6：一个客户端能连几个服务器？**
可以很多个。但要注意：工具总数太多时，模型容易选错，客户端也可能只显示前几十个。建议按项目启用，不用时关掉。

**Q7：工具太多，模型老选错怎么办？**
三招：① 只启用当前任务需要的；② 让工具名字和描述写清楚（"查订单"比"查询"好）；③ 在提示词里明确"先查再答，不要凭印象"。

**Q8：服务器挂了会怎样？**
那个服务器的工具暂时不可用，其他服务器和普通对话不受影响。好的客户端会提示"某个连接不可用"，而不是整个界面白屏。

**Q9：我的数据会被传到哪里？**
看服务器是本地还是远程：本地的基本不出机器；远程的一定会经过对方。接之前问清楚"存哪、存多久、会不会用于训练"。

**Q10：怎么判断一个服务器可不可信？**
四看：看来源（官方/知名开源）、看代码是否公开、看它要什么权限、看公司有没有批准。
**没搞清楚之前，别把真实客户资料接进去。拿假数据试。**

- 看到"握手""Session""SSE 长连接"的说法，先看文章日期：那是 2025 年的写法。

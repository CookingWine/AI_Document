这一篇回答一个很实际的问题：**这套东西和另外四套文档，到底谁管谁？**
这是最值得花五分钟弄懂的地方。五套东西管五件不同的事，**不互相替代**。

## 6.2 还是那家餐厅，多了一个角色

| 文档 | 餐厅里的东西 | 管什么 |
| --- | --- | --- |
| `AIRule` | 墙上的卫生守则 | 谁进厨房都得洗手，不用谁喊 |
| `AISkill` | 一本菜谱 | 做宫保鸡丁要翻到第 12 页，按步骤来 |
| `AIAgents` | 厨师本人 | 真正动手、自己判断先炒哪个 |
| `AIMCP` | **传菜窗口 / 进货接口** | 让厨房能拿到外面的食材、能把菜端出去 |
| `AgentWorkbench` | 一间样板厨房 | 把上面这些真的搭出来给人参观 |

窗口本身**不做菜、也不定规矩**。它只保证"单能递进来、菜能端出去、两边说的话对得上"。

---

## 6.3 出问题时怎么定位

| 现象 | 问题在哪一层 | 该改什么 |
| --- | --- | --- |
| 它动了没让它动的文件、编了没有的数字 | 边界 | 加一条 `AIRule` |
| 它做出来的东西结构不对、每次都不一样 | 做法 | 改 `AISkill` 的步骤和格式 |
| 它没查就答、查到一半停了、没人验收 | 执行 | 改派活方式，见 `AIAgents/04` |
| 它说"我访问不了那个系统" | 接口 | 加一个 MCP 服务器，或检查权限范围 |
| 它调了工具，但结果不对 | 服务器 | 查服务器本身，或换一个实现 |

## 6.4 三个最容易混的说法

**"MCP 是不是就是技能？"**
不是。技能是**做法**（先做什么、后做什么、什么不许做），MCP 是**接口**（怎么把工具接到 AI 面前）。
一个技能可以完全不碰 MCP（只是让 AI 按格式写周报）；一个 MCP 服务器也可以不带任何技能（只是提供"查天气"这个工具）。

**"MCP 能不能替代规则？"**
不能。MCP 服务器可以声明"我这个工具是只读的"，但这只是**建议**。真正的硬约束要写在产品代码里，或者由客户端在调用前拦截。见 [AgentWorkbench/07](../../AgentWorkbench/docs/07-工具与权限门.md) 里"软规则 / 硬规则"两层设计。

**"有了 MCP，是不是不用写提示词了？"**
不是。MCP 让 AI 够得着工具，但"什么时候该用哪个工具、用完怎么组织答案"仍然靠提示词和技能。工具越多，提示词越要写清"先查再答、不要凭印象"。

---

## 本篇要点

- 五层分工：**AIRule 边界、AISkill 做法、AIAgents 执行、AIMCP 接口、AgentWorkbench 落地**。
- MCP 是"传菜窗口"：不做菜、不定规矩，只保证两头说得上话。
- 定位口诀：**越界找规则，做错找技能，够不到找接口**。
- MCP 不能替代规则，也不能替代提示词。

## 8.1 九步走完

第一次接 MCP，照这个顺序走，不容易翻车。

| 步骤 | 做什么 | 做完应该看到什么 |
| --- | --- | --- |
| 1 | 选一个你已经在用的、支持 MCP 的客户端 | 设置里能找到"工具 / 连接器 / MCP"这类入口 |
| 2 | 选一个**只读**的服务器（文件读取、搜索这类） | 找到它的说明页，确认它只需要读权限 |
| 3 | 找到配置文件（或界面里的添加表单） | 知道该改哪个文件、改完要不要重启 |
| 4 | 填最小配置：只给它一个子文件夹，或只给只读凭证 | 保存后 JSON 没有报错 |
| 5 | 重启客户端，打开工具列表 | 能看到服务器名字和它的工具 |
| 6 | 问一个"必须查了才知道"的问题 | 它调了工具，答案里有依据 |
| 7 | 故意越界一次（让它读范围外的文件） | 它拒绝，或提示没有权限 |
| 8 | 打开调用记录看一眼 | 调用次数、参数、返回都说得清 |
| 9 | 填一遍 [接入清单模板](../templates/MCP-接入清单.md) | 六个安全问题的答案都写下来了 |

---

## 8.2 做完之后

**做完这九步，你已经超过了大多数人**——很多人是直接复制一段配置粘进去，从来没验过权限边界。

接下来做三件事：把填好的 [接入清单](../templates/MCP-接入清单.md) 存进项目；一周后再走一遍越界测试；确认不用时把服务器关掉。

---

## 本篇要点

- 九步：选客户端 → 选只读服务器 → 找配置 → 最小配置 → 重启 → 问必须查的问题 → 故意越界 → 看记录 → 填清单。
- 第 4 步和第 7 步最关键：一个定边界，一个验边界。
- 先在不重要的目录/账号上跑一周，再考虑接进日常环境。

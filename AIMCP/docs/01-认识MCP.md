# 01 认识 MCP

这一篇只回答一个问题：**为什么需要 MCP。** 先从没有标准时的样子看起。

---

## 1.1 先看没有标准时的样子

假设你公司有 8 个系统：文件柜、客户表、订单库、内部 wiki、邮件、日历、财务报表、代码仓库。
你手上有 5 个 AI 工具：聊天窗口、编辑器插件、桌面助手、命令行工具、公司自研的问答页。

没有统一标准时，每一个"AI × 系统"的组合都要单独写一套对接代码：

```
5 个 AI  ×  8 个系统  =  40 套对接
```

每加一个 AI，要写 8 套；每加一个系统，要写 5 套。写完之后还要各自维护——系统升级了，40 套里可能有 30 套要改。

有了统一标准之后：

```
5 个 AI  +  8 个系统  =  13 个适配
```

每个 AI 只要会"说这套标准话"（5 个适配），每个系统只要提供"符合这套标准的接口"（8 个适配）。任意组合都能通。

**打个比方**：以前每个牌子的电器配一种插头，出差要带一包转换头；后来统一成 USB-C，一根线走天下。MCP 就是 AI 世界的 USB-C。

> 这套标准由 Anthropic（一家人工智能公司）在 2024 年 11 月首次公开发布，后来交给 Linux 基金会下的 **Agentic AI Foundation** 托管，现在是跨厂商的公开标准，不属于任何一家公司。

---

## 1.2 它解决的三个具体麻烦

| 麻烦 | 没标准时 | 有 MCP 之后 |
| --- | --- | --- |
| 重复对接 | 每个 AI 都要为同一个系统写一遍 | 系统这边写一次，谁都能接 |
| 换工具就重做 | 换个 AI 客户端，插件全部重写 | 配置里改一行，工具照用 |
| 权限说不清 | 每个插件自己决定能碰什么 | 统一声明"我能做什么"，由客户端和你授权 |

---

## 1.3 它**不**解决什么

这一点很重要，能省你很多钱和时间：

| 你可能以为 | 实际上 |
| --- | --- |
| 装了 MCP，AI 就变聪明了 | 它只是多了几件工具，脑子还是那个脑子 |
| 装了 MCP，AI 就不会乱来了 | 安全靠权限配置和"人工确认"，不靠协议 |
| MCP 能记住我的偏好 | 记忆在别处（规则文件、技能文件、对话上下文） |
| MCP 是一个软件/插件市场 | 它只规定"怎么连"，不规定"去哪下载" |
| MCP 只适用于某一家 AI | 它是公开标准，多家客户端和模型都支持 |

---

## 本篇要点

- MCP 是 **AI 和外部工具之间的统一接口标准**，不是某一家产品的功能。
- 没有标准时是 `5 × 8 = 40` 套对接；有标准之后是 `5 + 8 = 13` 个适配。
- 它只解决"接得上"，不解决"变聪明""不乱来""记得住"。
- 判断值不值得用：你是不是要接很多工具，或者要换很多 AI。

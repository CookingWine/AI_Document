## 3.1 一次调用到底发生了什么

不用记协议细节，记住这六步就够了。这是所有 MCP 交互的骨架。

```
① 你提问
   "帮我查一下工号 E1003 的月薪"
        │
        ▼
② 模型判断：这需要查表，我不能凭印象答
   它输出一句结构化的"请求"：调用 query_rows，参数 {"rowId":"E1003"}
        │
        ▼
③ 客户端把这句话包装成标准消息，发给对应的服务器
   （本地程序就递过去，远程服务就发 HTTPS 请求）
        │
        ▼
④ 服务器执行：真的去查了那张表
        │
        ▼
⑤ 结果原路返回：{"ok":true,"rows":[{"月薪":"18000"}]}
        │
        ▼
⑥ 模型拿到结果，用中文回答你
   "E1003 的月薪是 18,000 元。"
```

四个必须理解的细节：

1. **模型没有直接执行任何代码。** 它只是"点了菜"，真正做菜的是服务器。这一点是全部安全设计的基础。
2. **模型看不到你的硬盘、你的数据库。** 它只能看到"服务器愿意返回给它的那部分内容"。
3. **结果要"回灌"给模型。** 服务器返回的不是给人看的漂亮话，而是一段结构化的数据；模型读完再翻译成人话。
4. **一次提问可能触发多次调用。** 比如先查有几个人、再查平均薪资、最后才回答。这个"想一步、做一步、看结果"的循环，就是 [AIAgents/02](../../AIAgents/02-任务是怎么跑完的.md) 里讲的循环。

## 3.2 两种连接方式：本地还是远程

MCP 只规定了两种"怎么把消息送到对方"的方式，术语叫**传输方式**（Transport）。你只要会区分这两种就够了。

| | 本地（stdio） | 远程（Streamable HTTP） |
| --- | --- | --- |
| 服务器在哪 | 你自己的电脑上 | 某个网址背后（别人或公司的机房） |
| 怎么连 | 客户端把这个小程序**启动起来**，通过"标准输入/输出"对话 | 客户端用 **HTTPS**（网页用的加密传输）发请求 |
| 要不要联网 | **完全不用** | 要 |
| 数据出不出本机 | 不出 | 会经过对方 |
| 配置里写什么 | `command` + `args` + `env` | `url` + `headers` |
| 典型用途 | 读本地文件、查本地数据库、跑本地脚本 | 公司内部系统、SaaS 服务、需要统一更新的工具 |
| 打个比方 | 楼下自己家的工具箱 | 打电话叫外卖 |

> **"标准输入/输出"是什么？**
> 每个程序都有两个看不见的"管子"：一个收（标准输入），一个发（标准输出）。两个程序可以用这两根管子直接传话，不经过网络。这就是 stdio 的全部秘密。
>
> 顺带说一句：早年还有一种叫 SSE 的方式，现在基本被 Streamable HTTP 取代了。看到旧教程里写 SSE，不用慌，知道它是"上一代远程连法"就行。

### 3.2.1 怎么选

| 你的情况 | 建议 |
| --- | --- |
| 工具只处理你本机的文件 | 本地（stdio） |
| 工具要连公司内部系统、且多人共用 | 远程 |
| 涉及客户名单、身份证号、合同金额 | **优先本地**；必须远程时先问清数据流向 |
| 只是想试一下、不想装东西 | 先从远程的只读服务开始 |

---

## 本篇要点

- 一次调用六步：**提问 → 模型点单 → 客户端传话 → 服务器执行 → 结果回灌 → 模型回答**。
- 模型不执行代码，它只是"点菜"；真正干活的是服务器。
- 本地 stdio 数据不出机器；远程 Streamable HTTP 一定会经过对方。
- 选型只看三件事：数据在哪、要不要共用、能不能接受出本机。

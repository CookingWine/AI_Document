## 4.1 配置文件长什么样

几乎所有客户端的配置格式都差不多：一个 JSON 文件，里面列着"我要连哪些服务器"。

> **JSON 是什么？** 一种"用大括号和引号写清单"的文本格式，人和机器都容易读。你不需要会写程序，只要会照着改**引号里的内容**就行。

### 4.1.1 本地服务器

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/你/Documents/工作资料"],
      "env": {}
    }
  }
}
```

逐行解释：

| 内容 | 意思 | 你要改吗 |
| --- | --- | --- |
| `mcpServers` | "服务器清单"的开始，固定写法 | 不改 |
| `"filesystem"` | 你给这个服务器起的**昵称**，随便起，只要不重复 | 可以改 |
| `"command": "npx"` | 要启动哪个程序。`npx` 是一个"按名字去下载并运行小程序"的工具 | 一般不改 |
| `"args"` | 传给这个程序的参数，一项一项写在方括号里 | **要改最后那一项**：把它换成你允许它访问的文件夹 |
| `"env"` | 环境变量，用来放密钥之类的东西（见 4.1.4） | 需要时填 |

**注意最后那个路径**：它就是这个服务器"能看到的世界"的边界。写 `Documents/工作资料`，它就看不到你的桌面、下载和照片。**这是最重要的一行。**

### 4.1.2 远程服务器

```json
{
  "mcpServers": {
    "company-crm": {
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${CRM_TOKEN}"
      }
    }
  }
}
```

| 内容 | 意思 |
| --- | --- |
| `"url"` | 远程服务器的地址，对方会给你 |
| `"headers"` | 附带的"身份凭证"。`Authorization: Bearer xxx` 是行业里最常见的写法，意思是"我带着这张通行证来" |
| `${CRM_TOKEN}` | 表示"从环境变量里取名为 CRM_TOKEN 的值"，**不要把真密钥直接写在这行** |

### 4.1.3 同时连多个

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/你/Documents/工作资料"]
    },
    "company-crm": {
      "url": "https://mcp.example.com/mcp"
    }
  }
}
```

用英文逗号分隔，最后一个不要加逗号。这是 JSON 最常见的报错原因。

### 4.1.4 密钥该放哪儿

**三条铁律**：

1. **不要写进配置文件。** 配置文件经常被截图、被同步、被提交到 Git。
2. **用环境变量。** 配置里写 `${变量名}`，真正的值放在系统的环境变量里。
3. **给最小权限的账号。** 专门建一个"只能读、只能看这一个库"的账号，别用你自己的主账号。

> **"环境变量"是什么？**
> 可以理解成操作系统里保存的一小组"名字 = 值"的设置，程序启动时能读到。它**不写在任何文件里**，所以不会跟着配置文件被截图、被同步、被提交到 Git。
> 在 Mac 上可以用 `export CRM_TOKEN="你的密钥"` 临时设置，或写进 `~/.zshrc`；Windows 在"系统属性 → 环境变量"里加。设置完要重开终端或客户端才生效。

> ⚠️ **一个真实的翻车场景**
> 有人把带 `sk-` 开头的密钥提交到了公开仓库，几分钟内就被扫描到并盗刷。
> 检查方法：提交前在项目里搜一下 `sk-`、`Bearer `、`password` 这几个词。

### 4.1.5 改完要重启

大多数客户端只在**启动时**读一次配置。改完文件必须重启客户端，或者用它的"重新加载"按钮。否则你会以为配错了，其实是没生效。

## 4.2 怎么确认"真的接上了"

配好不等于接上。按这四步验，从轻到重。

### 4.2.1 第一步：看列表

打开客户端的"工具 / 连接器 / MCP"面板，应该能看到你刚配的服务器名字，以及它提供的工具清单。

- 看得到 → 说明进程起来了、握手成功了。
- 看不到 → 先查三件事：配置文件路径对不对、JSON 有没有语法错（多一个逗号也算）、程序装没装。

### 4.2.2 第二步：问一句"必须用工具才能答"的话

不要问"你能做什么"（它会背简介），要问一个**只有查了才知道**的问题：

```
帮我看看工作资料文件夹里，上周的会议记录有几个文件？
```

期待的反应：它去调工具、然后告诉你数量。
不该出现的反应：它直接编一个数字，或者说"我无法访问文件"。

### 4.2.3 第三步：故意越界

这是最有效的一步。挑一条你最在意的边界，主动试探：

```
把 /Users/你/Desktop 里那个合同文件也读一下。
```

（如果你的配置只授权了 `Documents/工作资料`）

**期待的反应**：它说"这个路径不在我能访问的范围内"。
**不该出现的反应**：它真的读出来了——说明你给的权限比你以为的大。

### 4.2.4 第四步：看记录

好的客户端会留下调用记录：什么时候调了哪个工具、参数是什么、返回了什么。翻一遍，确认三件事：

1. 它只调了该调的；
2. 参数里没有多余的东西（比如把整张表都拉下来）；
3. 没有你看不懂的对外请求。

> 💡 **一个容易忽略的细节**
> 有些工具的名字在不同服务器里会重复，客户端通常会给它加前缀，变成 `服务器名.工具名`。看到 `filesystem.read_file` 这种写法，别以为是两个东西，它是"昵称.工具"。

---

## 本篇要点

- 配置就是一个 `mcpServers` 清单：本地写 `command / args / env`，远程写 `url / headers`。
- 最该改的一行是"允许访问的路径"——**它就是权限边界**。
- 密钥用环境变量，不写进文件；改完配置要重启。
- 验证四步：看列表、问必须查的问题、故意越界、看调用记录。

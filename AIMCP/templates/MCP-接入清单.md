# MCP 接入清单（模板）

> **这是什么**：接一个 MCP 服务器之前、之中、之后要填的一张表。复制一份，把方括号里的内容换成你的实际情况。
> **为什么要有**：MCP 服务器是"别人写的、能碰到你数据的程序"。凭感觉接，早晚出事；照着填一遍，问题在接之前就暴露了。
> **怎么用**：新建一个文件（比如 `mcp-接入-客户系统.md`），把下面从"一、接之前"开始的内容整段复制过去，逐项填。
> **相关阅读**：[MCP 说明](../README.md) ｜ [05 安全边界](../docs/05-安全边界.md) ｜ [06 与项目文档的关系](../docs/06-与项目文档的关系.md) ｜ [规则模板](../../AIRule/templates/RULE-模板.md)

---

## 使用说明（填完请删掉这一节）

1. 一个服务器填一份，不要几个混在一张表里。
2. 方括号 `【】` 里的是要你替换的内容；填不出来的项，写"不清楚"，**不要空着**——空着会让你以为没风险。
3. 第六节"安全复盘"里任何一项写了"否"，就先别接。
4. 填完把这份表存在项目里，和配置文件放在一起。三个月后你会需要它。

## 一、接之前：先回答六个问题

| # | 问题 | 答案 | 判断 |
| --- | --- | --- | --- |
| 1 | 它是谁做的？源码能看吗？ | 【厂商 / 开源项目地址】 | 来源不明 → 停 |
| 2 | 它要读什么、写什么？ | 【读：订单表；写：无】 | 说不清 → 停 |
| 3 | 数据存在哪？会不会传到第三方？ | 【本地 / 某云 / 不清楚】 | 不清楚 → 停 |
| 4 | 它要什么凭证？这个凭证还能干别的吗？ | 【只读账号 / 全权限账号】 | 全权限 → 换只读 |
| 5 | 出问题怎么撤？有日志吗？ | 【关掉配置即可 / 有调用记录】 | 撤不掉 → 停 |
| 6 | 公司 IT / 法务批准了吗？ | 【已批准 / 待批】 | 未批 → 停 |

**结论**：【可以接 / 先补条件 / 不接】

> 六项里有任意一项答不上来或写了"否"，就停在这一步。接上去只需要五分钟，收拾起来可能要五天。

## 三、权限设计：给到最小

先填"我想要什么"，再填"最少需要什么"，两者取小的那个。

| 项目 | 我希望它能 | 它最少需要 | 实际给它的 |
| --- | --- | --- | --- |
| 能访问的目录 / 库 / 表 | 【整个工作目录】 | 【只读这一个子文件夹】 | 【】 |
| 读 | 【是】 | 【是】 | 【】 |
| 写 / 改 | 【是】 | 【否】 | 【】 |
| 删 | 【否】 | 【否】 | 【】 |
| 对外发送（邮件、消息） | 【否】 | 【否】 | 【】 |
| 能看到的字段 | 【全部】 | 【去掉手机号、身份证号】 | 【】 |
| 凭证类型 | 【我的主账号】 | 【只读专用账号】 | 【】 |

**三条铁律自检**

- [ ] 只给了完成任务必需的那一小块，没有"顺手多给"
- [ ] 第一次接是只读的，没有一上来就给写权限
- [ ] 删除 / 覆盖 / 对外发送 / 付款，这四类都要求人工确认

```json

  "mcpServers": {
    "【昵称】": {
      "command": "【npx】",
      "args": ["【-y】", "【包名】", "【允许访问的路径】"],
      "env": {}
    }
  }

```

| 项目 | 内容 |
| --- | --- |
| 配置文件路径 | 【例如客户端设置里的连接器配置】 |
| 服务器昵称 | 【】 |
| 版本 / 包名 | 【写死版本号，不要用 latest】 |

## 七、出事怎么退

按顺序执行，每步做完记一笔。

1. **先断**：停用或删除这条服务器配置，重启客户端。（工具立刻不可用，数据不再流动）
2. **再查**：翻调用记录，看它调了什么、参数是什么、返回了什么。
3. **后评**：判断影响范围——读了哪些数据、改了哪些记录、发出去了什么。
4. **再恢复**：如果数据被改，用备份或版本历史恢复；不要靠"再让它改回去"。
5. **最后记**：把这次事故写进这份清单的末尾，包括时间、原因、处理、以后怎么防。

> 顺序不能反。先断再查，是为了防止它在你看记录的时候继续动作。

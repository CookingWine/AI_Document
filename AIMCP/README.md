## 先读这个：用三句话认识 MCP

**第一句**：AI 会"用工具"——能查资料、读文件、调接口。但每接一个新工具，都要单独对接一次，工具越多越乱。

**第二句**：MCP（Model Context Protocol，模型上下文协议）是一套**公开的接口标准**，规定"AI 这一端"和"工具那一端"该怎么说话。

**第三句**：有了这个标准，**工具做一次，所有支持 MCP 的 AI 都能用**；换个 AI，也不用把工具重做一遍。

一句话记住：**MCP 不是某个软件的功能，它是 AI 和外部世界之间的"统一插口"。**

> 名字拆开看就好懂了：
> - **Model**（模型）= 那个会思考、会写东西的 AI；
> - **Context**（上下文）= 它回答问题时能看到的资料；
> - **Protocol**（协议）= 双方约定好的一套说话规矩。
>
> 合起来：**规定"AI 通过什么方式、按什么格式拿到外部资料和工具"的一套规矩。**

## 三条阅读路径

不用按顺序读完。看你是哪种情况。

**路径一：想系统搞懂（约 40 分钟）**

```
01 认识 MCP → 02 角色与能力 → 03 调用与连接
   → 04 配置与接入 → 05 安全边界
```

**路径二：今天就要接一个（约 20 分钟）**

```
04 配置与接入（照着改配置）
   → 05 安全边界（只看"三条铁律"和"接前六问"）
   → 08 上手指南（九步逐项打勾）
```

**路径三：已经出问题了**

```
09 常见问题（先看旧教程辨识与误区）
   → 05 安全边界（越界、注入、权限）
   → 04 配置与接入（四步重新验一遍）
```

遇到不懂的词，随手翻 [10 术语表](./docs/10-术语表.md)。

```
   │

   ├─▶ 07 与 AI 开发的关系    （进阶，读完 02、05 再看）
   ├─▶ 08 上手指南            （随时插入，动手时用）
   ├─▶ 09 常见问题            （随时查）
   └─▶ 10 术语表              （随时查）
```

四条规则，记住就不会乱：

1. **`README.md` 是唯一入口。** 任何人不该"从中间某篇开始摸索"，入口永远先给这篇。
2. **01 → 05 是学习顺序。** 倒着读会缺前提，比如没看 02 的角色，就看不懂 04 里"客户端去启动服务器"是什么意思。
3. **06、07 是横向的两篇。** 一个管"在本项目里怎么定位"，一个管"往开发走怎么用"，不参与顺序阅读，但都值得看一遍。
4. **08、09、10 随时插入。** 一篇是清单，一篇是答疑，一篇是字典；都不复述道理。

每篇开头都标了"读这篇之前"，结尾都标了"上一篇 / 下一篇"，跟着走不会迷路。

## 维护约定

1. **协议会变，这两处要跟着变。** 每次官方发布新版本，回来改 [09 的旧教程表](./docs/09-常见问题.md) 和 [10 术语表](./docs/10-术语表.md)；不确定的地方标注"以官方文档为准"。
2. **不写具体产品的操作路径。** 各家客户端改版频繁，写了就会过期；只写"去设置里找工具 / 连接器 / MCP 这类入口"。
3. **例子必须能跑。** 配置示例里的路径、参数都是示意，但要保证结构正确、字段名正确。
4. **引用一律用相对路径。** 写 `../AIRule/README.md`，不写本机绝对路径。
5. **05 的风险表只增不删。** 出了新的攻击方式就补一行；旧的不删，因为旧系统还在跑。

**新增一篇的步骤**

1. 在 `docs/` 下按序号命名，比如 `11-团队共用.md`。
2. 复制任意一篇的文件头（所属、读前、读完、相关文件），改成自己的。
3. 在本页"文件索引"表里加一行，并在"文件之间的关系"图里补一个分支。
4. 上一篇的结尾导航加一个"下一篇"，新篇开头写"上一篇"。
5. 检查所有相对链接，确认没有指向旧文件名。

## 最后一句话

MCP 的价值不在于"多了一个酷炫功能"，而在于**它把"接工具"这件事从"每家各写一遍"变成了"按标准插一下"**。

但也别神化它：它只是让 AI 够得着。够得着之后会不会乱来，仍然取决于你有没有划边界、有没有留确认、有没有记日志。

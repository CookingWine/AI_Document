## 一、AIAgents 简介

### 1.1 什么是 AIAgent

**大白话**：一个能自己动手把事情做完的 AI，而不只是陪你聊天的 AI。

**打个比方**：聊天机器人像**电话客服**——你问一句它答一句，挂了电话它就不再管你的事；AIAgent 像**派出去办事的同事**——你说"把这份周报整理好发给团队"，他会自己找文件、自己排版、自己发送，中间遇到问题才回来问你。

一个 AIAgent 通常由四块拼起来：

| 组成 | 作用 | 缺了会怎样 |
| --- | --- | --- |
| 大脑（大模型） | 理解你的目标、判断下一步做什么 | 无法理解意图 |
| 手脚（工具） | 读写文件、执行命令、调用接口、上网查资料 | 只能空谈，落不了地 |
| 记忆（上下文） | 记住这次任务里已经做了什么 | 每步都要你重新交代 |
| 规矩（技能） | 知道这类活按什么标准干 | 每次做法都不一样 |

前三块由平台提供，**第四块才是你需要自己写的**——也就是本文档的主角：AISkill。

### 1.2 AIAgent 和聊天机器人的区别

| 维度 | 聊天机器人 | AIAgent |
| --- | --- | --- |
| 交互方式 | 一问一答，你推一下它动一下 | 给一个目标，它自己拆步骤往下做 |
| 能不能碰文件 | 不能，除非你粘贴内容给它 | 能读、能改、能新建文件 |
| 任务长度 | 单轮为主，说长了自己就忘 | 可以连续做几十步，直到任务完成 |
| 结果稳定性 | 每次说法不同 | 有技能约束后，产出趋于一致 |

### 1.3 AIAgents 在这个文档空间里的定位

`AIAgents/` 是承载"智能体怎么用、怎么教它干活"的目录。目前收录的是一份基础能力说明：

```
AI_Document/
├── AIAgents/                 ← 你在这里：智能体的使用说明
│   └── AISkill说明文档.md     ← 本篇：技能是什么、怎么用
└── AISkill/                  ← 配套手册：完整教程与模板
    ├── README.md
    ├── docs/                 ← 九篇正文
    ├── templates/            ← 两个可复制填空的模板
    └── CHANGELOG.md
```

两者的分工很清楚：**本篇讲"是什么、为什么、怎么开始"**，`AISkill/` 目录讲"每一处细节怎么做"。想深入时再翻手册，不必一上来就读完九篇。

## 二、AISkill 的用途说明

### 2.1 一句话定义

**AISkill 就是把"你要交代给 AI 的那番话"提前写成文件，存起来重复使用。**

现在的 AI 像一个刚入职的实习生：书读得多、脑子快，但完全不了解你的工作、你的习惯、你公司的规矩。你交代得越具体，它做得越对；交代得含糊，它就自由发挥。

AISkill 要解决的就是这件事——**把口头交代变成书面规矩**。

### 2.2 它解决三个具体问题

| 问题 | 没有技能时 | 有了技能之后 |
| --- | --- | --- |
| **重复交代** | 每次干活都要重新说一遍"我是谁、要什么格式、别写客套话" | 说一句"按周报技能来"，剩下的它自己知道 |
| **输出飘忽** | 同样的话，今天写三段、明天写五段，语气也不一样 | 同一份技能，产出结构和口径基本固定 |
| **经验留不住** | 你摸索出的好写法只在这一次对话里，关掉就没了 | 写进文件、进版本库，全团队都能用，还能迭代 |

### 2.3 什么活适合做成技能

| 适合 | 为什么 | 例子 |
| --- | --- | --- |
| 周期性重复的活 | 一次投入，长期复用 | 周报、月报、会议纪要 |
| 有固定格式要求的活 | 格式能写成明确条款 | 合同摘要、竞品对比表 |
| 有明确对错标准的活 | 标准可以写成检查项 | 文案合规检查、数据清洗 |
| 需要固定角色口吻的活 | 人设能写进文件 | 客服回复、教学讲解 |

| 不适合 | 为什么 |
| --- | --- |
| 一辈子只做一次的活 | 写技能的时间比干活还长 |
| 每次要求都不同的活 | 写死了反而碍事，直接说更快 |
| 需要实时判断、无法预先描述的活 | 技能只能写"已知的规矩"，写不了"临场发挥" |

判断标准很简单：**这件事你一个月内会不会做第二次？会，就值得写。**

### 2.4 别把几个词搞混

| 词 | 大白话 | 类比 |
| --- | --- | --- |
| 提示词（Prompt） | 你这一次对 AI 说的话 | 当面口头交代一句 |
| AISkill | 把这类活的做法写成文件长期保存 | 写成《岗位操作手册》 |
| 上下文（Context） | AI 当前能看到的全部信息 | 他桌上的那叠材料 |
| AIAgent | 拿着手册、能自己动手干活的 AI | 拿着手册上岗的员工 |

关系是层层包含的：**AIAgent 靠上下文理解任务，靠技能保证做法，靠提示词接收这一次的具体指令。**

## 三、使用指引

### 3.1 三步快速上手

**第一步：挑一件小事。** 选你每周都要重复做、且格式相对固定的一件事，比如写周报。不要一上来就做"全公司流程"，做不完会挫败。

**第二步：写一份最小技能。** 不用代码，不用特殊软件，就是新建一个 `.md` 文本文件，按下面这个骨架填：

```markdown
# 周报生成

## 什么时候用
用户说"写周报""本周总结""周报模板"时。

## 我是谁
电商公司客服主管，团队 5 人。

## 怎么做
1. 先问用户要三个数据：本周咨询量、主要问题、下周重点。
2. 按"本周数据 / 主要问题 / 下周计划"三段写。
3. 每段不超过 100 字，语气正式，不用感叹号。
4. 如果用户没给数据，先用【待补充】占位，不要编造数字。

## 不要做什么
- 不要写"感谢领导"之类的客套话。
- 不要自己编造没提供的数字。
```

**第三步：试跑一次。** 把这份文件交给 AI，说"按这个技能写本周周报"，看产出对不对。不对就改文件里对应的那一条，再试。

### 3.2 一份技能由哪几部分组成

| 部分 | 回答的问题 | 是否必需 |
| --- | --- | --- |
| 什么时候用 | 什么话术下该触发这个技能 | 必需，写不清就不会被调用 |
| 我是谁 | 什么角色、什么行业、服务谁 | 建议有，决定口吻和专业度 |
| 怎么做 | 分几步、每步要什么、输出什么格式 | 必需，这是主体 |
| 不要做什么 | 哪些坑不能踩 | 强烈建议，往往比"要做什么"更重要 |
| 参考样例 | 一段合格产出长什么样 | 可选，但效果提升明显 |

最后一条值得强调：**AI 犯的错，八成是你不想要、但它觉得"顺手"就加上的东西。** 所以"不要做什么"这一节别省。

### 3.3 标准目录结构

单个技能可以就是一个文件；技能多了以后，建议按下面这个结构收拢：

```
my-skill/
├── SKILL.md          ← 技能本体：什么时候用、怎么做、不要做什么
├── templates/        ← 需要填空的模板
├── examples/         ← 一份合格样例，供 AI 对照
└── README.md         ← 写给同事看的说明书
```

新手期只写 `SKILL.md` 就够了，不要为了结构完整而多写四个空文件。

### 3.4 制作流程概览

从零到能用，一共九步。每一章的详细说明在手册里，这里只给路线图：

1. **确认场景**——这件事是否重复、是否有固定标准。
2. **收集素材**——把过去做过的三五份合格产出找出来，那是标准的来源。
3. **写"什么时候用"**——列出用户可能说的几种话术。
4. **写"我是谁"**——角色、行业、服务对象、口吻。
5. **拆步骤**——一步只做一件事，按真实做的顺序写。
6. **写输出格式**——段落、字数、表格列名，越具体越好。
7. **写禁区**——把你被坑过的点逐条列上。
8. **贴样例**——附一段合格产出。
9. **存档并试跑**——放进版本库，跑一次，按结果回改。

对应手册：[04 制作步骤](../AISkill/docs/04-制作步骤.md)

### 3.5 怎么用、怎么判断生效了

| 动作 | 做法 |
| --- | --- |
| 触发 | 提到技能名，或说技能里写明的触发词（如"写周报"） |
| 显式指定 | 说"用周报技能来做"，避免它自由发挥 |
| 提供素材 | 把本周数据、参考文件一并给出，别让它猜 |
| 判断是否生效 | 看三点：结构是否和技能一致、格式是否合规、禁区是否被遵守 |

如果三点里有任何一条不符，**不要在和它的对话里反复纠正**——那属于一次性修补，下次还犯。正确做法是回到技能文件，把缺的那条规矩补进去。

对应手册：[05 使用方法](../AISkill/docs/05-使用方法.md)

### 3.6 写完自查清单

交付前对着这张表过一遍，任一项打不了勾就先别发布：

- [ ] 触发条件写清了，别人看了也知道什么时候该用
- [ ] 每一步只做一件事，顺序和实际操作一致
- [ ] 输出格式具体到段落、字数、字段名
- [ ] 至少有三条明确的禁区
- [ ] 附了一份合格样例
- [ ] 没有出现"尽量""适当""好看一点"这类无法执行的词
- [ ] 全文没有写死的本机路径
- [ ] 已经用真实任务试跑过一次
- [ ] 改动记录进了变更日志

完整版九项验收标准见：[06 质量检查](../AISkill/docs/06-质量检查.md)

### 3.7 新手最容易踩的五个坑

| 坑 | 表现 | 改法 |
| --- | --- | --- |
| 写成了愿望清单 | "要专业、要准确、要有深度" | 换成可执行动作："每段不超过 100 字，引用数据须标来源" |
| 一份技能干十件事 | 从写稿到发布全塞进去 | 拆成多份，一份只干一类活 |
| 只写"要做什么" | 产出总带着你不想要的客套话 | 补"不要做什么"，逐条列 |
| 触发条件含糊 | 该用它时没被调用 | 把用户可能说的原话列进"什么时候用" |
| 从不试跑 | 文件写完就发给同事 | 先用真实任务跑一遍再交付 |

## 四、维护约定

这份文档和 `AISkill/` 手册是一套东西，改动时守住三条：

1. **一处定义，多处引用。** 技能的定义只在本篇第二章讲一次，手册里不重复展开，需要时链接过来。
2. **引用一律用相对路径。** 写 `../AISkill/README.md`，不写本机绝对路径，换台电脑也能打开。
3. **改了就记一笔。** 结构性调整同步更新 `AISkill/CHANGELOG.md`，写清"改了什么"，不写"更新"。

## 最后一句话

不要等"学会了"再动手。挑一件你每周都要重复做的小事，用 20 分钟写个十行的技能文件，试一次。**做出来那份粗糙的东西，比读完十篇教程有用。**

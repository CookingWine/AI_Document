## 3.1 三个判断条件

一件事值不值得交给 agent，看三条，缺一条就别急：

| 条件 | 问自己 | 不满足会怎样 |
| --- | --- | --- |
| **说得清** | 我能不能用三句话说清要什么、不要什么 | 它只能猜，产出靠运气 |
| **验得了** | 结果对不对，我能不能在十分钟内看出来 | 你无法判断它交的是好是坏 |
| **退得回** | 做错了能不能撤回、有没有备份 | 一次失误就是永久损失 |

三条都过，放心派；缺"验得了"，先想清楚验收标准再派；缺"退得回"，先做备份，或者只给它只读权限。

---

## 3.2 适合与不适合

| 适合交给 agent | 为什么 | 例子 |
| --- | --- | --- |
| 步骤多但每步都明确的活 | 它能连着做，不用你盯 | 一批文档转格式 + 抽字段 + 汇总成表 |
| 要跨多个工具搬数据的活 | 人手搬容易错、费时间 | 从网页取数 → 清洗 → 写进表格 |
| 每次情况都不太一样的活 | 需要临场判断，脚本写不死 | 按不同客户资料生成不同方案初稿 |
| 需要先查再答的活 | 它能自己检索、自己核对 | 竞品资料调研与对比 |

| 别交给 agent | 为什么 | 换什么办法 |
| --- | --- | --- |
| 一次性的小事 | 描述成本高于自己做 | 自己两分钟搞定 |
| 规则完全固定、天天一样的活 | agent 有成本、有延迟、还会飘 | 写成脚本或工作流 |
| 结果无法验证的活 | 你分不清它对错，等于赌博 | 先想办法建立验收标准 |
| 不可逆且高风险的活 | 一次失误无法挽回 | 人来执行，agent 只做准备 |
| 需要专业资质判断的活 | 法律、医疗、审计结论不能靠它 | 它做初稿，人签字 |

## 3.3 六类典型场景

| 场景 | agent 干什么 | 你负责什么 |
| --- | --- | --- |
| 文档批量处理 | 批量重命名、转格式、抽字段、合并 | 定规则、抽查 10% |
| 资料检索与综述 | 多来源检索、去重、比对、成稿 | 定问题、判断来源可信度 |
| 数据整理与分析 | 清洗、算指标、出图、写结论 | 定口径、复核结论 |
| 代码修改 | 定位问题、改代码、跑测试 | 定需求、审 diff |
| 例行巡检 | 查日志、比配置、出报告 | 定阈值、处理异常 |
| 跨工具流程 | 搬数据、发通知、更新状态 | 授权、兜底 |

共同点：**agent 干"量大、步骤多、需要判断"的部分，人干"定标准、判可信、签字"的部分。** 一旦你发现自己只是在等它出结果、却完全不知道该怎么验，说明这一步派错了。

---

## 3.4 它能干，但你别放手

| 红线 | 风险 | 正确做法 |
| --- | --- | --- |
| 删除、覆盖、批量改写 | 不可逆，尤其是没有版本管理的目录 | 先备份，或只给只读；删除走回收站 |
| 对外发送：邮件、发布、付款 | 发出去就收不回 | 让它起草，人来点发送 |
| 权限与密钥 | 一次泄露长期受害 | 不把密钥贴进对话；用最小权限账号 |
| 合规与专业结论 | 出错责任在人不在它 | 它出初稿，人复核并署名 |

这条边界不是不信任技术，是**成本不对称**：让它多干一步省你十秒，出了事你要花十小时收拾。

---

## 3.5 什么时候用脚本，什么时候用 agent

| | 脚本 | Agent |
| --- | --- | --- |
| 输入 | 每次格式一样 | 每次不一样 |
| 异常 | 提前写死分支 | 临场判断 |
| 成本 | 几乎为零 | 每次都有调用成本与延迟 |
| 可预测性 | 高，跑一万次都一样 | 中，同一句话可能两种走法 |
| 适合 | 每天重复、格式固定的活 | 情况多变、需要判断的活 |

判断方法：**如果这件事你能一遍遍写出完全相同的操作步骤，那就写脚本；如果你每次都要先看一眼情况再决定怎么做，那才用 agent。** 稳定到能写成脚本的活交给 agent，是在为"不确定"付冤枉钱。

---

## 本篇要点

- 三个条件缺一不可：**说得清、验得了、退得回**。
- 判断标准不是"AI 能不能做"，而是"**做完我能不能验、错了能不能退**"。
- 四类操作人来点：不可逆操作、对外发送、权限密钥、专业结论。
- 规则固定到能写死，就用脚本；agent 的价值在**处理不确定**。

## 6.1 把做法固化下来

同一类活派到第三遍，你大概率在重复说同样的话。这时候该把这段话变成技能文件——**派活的话是给这一次的，技能文件是给每一次的**。

| | 派活的话 | 技能文件 |
| --- | --- | --- |
| 生效范围 | 这一次对话 | 以后每一次 |
| 谁看 | 当前这个 agent | 任何接手的 agent |
| 形态 | 聊天里的一段话 | 仓库里的一个 `.md` |
| 怎么来 | 随口说 | 把跑顺的那段话整理成条款 |

具体怎么写，看 [AISkill 04 制作步骤](../AISkill/docs/04-制作步骤.md)，模板在 [SKILL-模板](../AISkill/templates/SKILL-模板.md)。这套文档不重复讲。

判断时机的信号：**同一类活派到第三遍、每次派活的话超过五段、每次都要解释同样的禁令。**

---

## 6.2 什么时候需要多个 agent

单个 agent 能做完的，别拆。拆成多个只在两种情况下划算：

- **活太长，一个上下文装不下**：比如读完 200 份文档再写综述，拆成"分批读 + 汇总"。
- **需要相互检查**：一个写、一个挑错，比一个自查更可靠。

拆的代价是**信息在交接处丢失**，所以交接时必须给结构化产物（清单、表格、明确结论），不能只说"上面那些你自己看"。

---

## 6.3 五个典型误区

| 误区 | 表现 | 改法 |
| --- | --- | --- |
| 一句话派大活 | "帮我整理下资料" | 用五段式，先把范围缩到十分钟能验的规模（[04 篇](./04-怎么把活派出去.md)） |
| 把它当搜索引擎 | 直接信它给的数字和出处 | 要求标来源，关键数字自己复核 |
| 不设停止条件 | 它自作主张删了文件、发了邮件 | 明确"遇到 X 先问我" |
| 只看总结不看过程 | 结果对了，别处被改坏 | 每次要改动清单，做"查副作用"（[05 篇](./05-怎么监督与验收.md)） |
| 每次都从头交代 | 同一类活派了十遍，每遍都在重复 | 第三遍起固化成技能（见 6.1） |

---

## 本篇要点

- **第三遍**是固化信号：同类活派到第三遍，就该写成技能文件。
- 派活的话是消耗品，技能文件是资产；前者只活一次对话，后者会被反复读取。
- 多个 agent 只在"上下文装不下"或"需要相互检查"时值得拆，代价是交接处丢信息。
- 五个误区里最费钱的是"一句话派大活"，最容易忽略的是"只看总结不看过程"。

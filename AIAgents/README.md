## 三条阅读路径

不用按顺序读完。看你是哪种情况。

**路径一：想系统搞懂（约 25 分钟）**

```
01 认识 → 02 怎么跑 → 03 什么活该交 → 04 怎么派 → 05 怎么验
```

**路径二：不想听道理，马上要派活（约 10 分钟）**

```
04 怎么派（照五段式写）→ 07 速查（派完对着清单过一遍）
   判断不了该不该交，先看 03
```

**路径三：已经出问题了**

```
先看 05 验收四查 → 再看 06 五个误区
   技能层面怎么写更好，翻 AISkill 手册
```

两条规则，记住就不会乱：

1. **01 → 05 是学习顺序。** 倒着读会缺前提，比如没看 02 的循环，就看不懂 05 为什么强调"查副作用"。
2. **07 是唯一可以随时插入的一篇。** 它只放清单，不复述道理；道理都在 01–06。

## 维护约定

1. **一篇只讲一件事。** 想加的内容放不进现有任何一篇，才新建文件，并更新本页索引、结构图和引用关系图。
2. **这套文档只管任务层。** 技能怎么写、怎么验，一律链接到 `AISkill/docs/`，不在这里复述，避免同一件事两处维护、两处走样。
3. **引用一律用相对路径。** 写 `../AISkill/README.md`，不写本机绝对路径。
4. **变更以提交记录为准。** 目录内不再单独维护变更日志，`git log -- AIAgents/` 就是这套文档的历史。
